## 1. Что это
Аналитический ретеншн-CRM для онлайн-казино поверх **ClickHouse + Flask-дашборд**.
По каждому игроку: прогноз ценности (LTV), риск ухода, вероятность депозитов, и **движок офферов**
«кому / когда / какой бонус». Цель — удержание, повторные депозиты, рост LTV.

**Данные:** ClickHouse БД `retention`, ~39 010 реальных игроков (`account_type='normal'`),
54M ставок, период дек 2025 → июнь 2026, валюта TRY. Только localhost, PII не наружу.

## 4. Модели (6, в `*_model.py`, обучаются `./train_all.sh`)
| Модель | Файл → таблица | Качество |
|---|---|---|
| LTV D90 (регрессор) | ltv_model.py → player_ltv_ml | Spearman **0.891**, топ-10%=74% денег |
| LTV квантили P10/50/90 | ltv_quantiles.py → player_ltv_quantiles | покрытие 79.8% |
| P(2-й депозит, 30д) | repeat_model.py → player_repeat_ml | AUC 0.67 |
| Риск ухода (churn, point-in-time) | churn_model.py → player_churn_ml | AUC **0.733** |
| P(след. депозит) | deposit_ladder_model.py → player_next_deposit_ml | AUC **0.90** |
| Бонус-отклик + uplift | bonus_model.py → player_bonus_ml, bonus_uplift | AUC 0.65 (слабо) |

**Движок офферов** = view `player_actions`: `приоритет = ценность × вероятность ухода`, действие
(SAVE/WINBACK/NUDGE/CONVERT/NURTURE), бонус по правилам, когда.

⚠️ **Название алгоритма в UI замаскировано** (`CatBoost` → `********` в player_board.py и FORMULAS.md),
чтобы не светить технологию при показе. В коде моделей (`from catboost import …`) — НЕ трогать, это рабочие импорты.

## 5. Архитектура / поток данных
`schema.sql` (4 сырые таблицы) → загрузка данных → `player_features.sql` (витрина, 1 строка/игрок)
→ `marts.sql` (10 вьюх + ML-таблицы пустые + наполняемые `player_games`/`bonus_effectiveness_t`)
→ `./train_all.sh` (обучает 6 моделей, наполняет ML-таблицы) → `player_board.py` (читает всё live).

> Это **текущий batch/offline-поток**. Куда развивается (сервинг ML с train/score split и registry,
> приём данных от внешних систем по контракту, настоящий real-time трекинг через стрим) — живой
> документ **[ARCHITECTURE.md](ARCHITECTURE.md)**, там думаем «как и что» дальше. Перенос обученных
> таблиц между серверами без переобучения: `dump_ml_tables.sh` / `restore_ml_tables.sh`.

**Ключевые файлы:** player_board.py (дашборд, ~1900 строк) · schema.sql · player_features.sql ·
marts.sql · 6×`*_model.py` · train_all.sh · requirements.txt (борд) + requirements-ml.txt (обучение) ·
SETUP.md (пошаговый деплой на VPS) · migrate_to_server.sh · FORMULAS.md · COHORTS.md · ML_PLAN.md.

## 7. Честные оговорки (важно для следующего)
- **Bonus uplift ≈ 0.** Квазиэксперимент: сырой разрыв «с бонусом vs без» +34 п.п. — это почти весь ОТБОР
  (бонусы дают и так активным). Честная добавка ~+1.7 п.п., CI пересекает ноль. Бонус-рекомендатель
  слабый (AUC 0.65) → в движок НЕ вшит, выбор бонуса по правилам. Чтобы исправить — нужен **A/B-тест**.
- **Модели калиброваны на РАНЖИРОВАНИЕ, не на абсолютную вероятность** — использовать для приоритизации.
- **`player_features` — статичная витрина** → поля от `today()` (recency/lifecycle) замораживаются на дату
  сборки. Обновлять пересборкой витрины + переобучением (cron). `churn_model.py` имеет хардкод дат срезов.
- **Чего нет в данных** (не сделать без выгрузки): ROI трафика (нет costs), sportsbook, канал доставки
  (telegram/whatsapp пусто), GEO-вариация (всё TR).
- **Churn скорится только для ~1041 активных** (нельзя предсказать уход у тех, кто уже ушёл/не играл) — by-design.
