# Lifecycle-плейбук Revenue Autopilot: как строятся retention-кампании

База знаний для мастер-промптов (ai_compose) и детерминированных правил
(compose.py). Дистиллят практик: Baremetrics/ProfitWell (dunning-статистика),
Churnkey/Brightback (cancel-флоу), Reforge (lifecycle-фреймворки), паттерны
email-программ Intercom/Customer.io. Каждое правило здесь - причина, по
которой промпт или генератор написан именно так.

## 1. Типы кампаний (рычаги) и их физика

| Рычаг | Триггер | Почему работает | Окно |
|---|---|---|---|
| **Activation** | Зарегался, не дошёл до ценности за 24-72ч | Первые 48ч решают: не увидел ценность = не заплатит никогда. Друг за другом: убрать трение, показать простейший путь, дать безрисковый старт (бонус-юниты) | 48ч-7д |
| **Trial conversion** | Триал кончается через <=3д, оплаты нет | Дедлайн - главный конвертер. Loss-frame («не потеряй сделанное») сильнее discount-frame. Продление триала конвертит недорешивших без скидки | T-3..T+3 |
| **Dunning** | payment_failed / past_due | 20-40% чурна - невольный (карта). Комбинация ретраев и писем возвращает 30-70% несписаний. Тон - сервисный, НЕ обвинять, работа сохранна | 0ч, 24ч, 72ч, 7д |
| **Save** | Открыл cancel-флоу / упала активность | Пауза вместо отмены спасает 10-30% уходящих. Скидка - ПОСЛЕДНИЙ аргумент (иначе учишь торговаться). Сначала: пауза, downgrade, напоминание ценности (сделанное юзером) | немедленно |
| **Upgrade** | Сжёг 80%+ лимита плана | Момент боли лимита = момент апгрейда. ROI-фрейм («на Pro юнит дешевле»), не feature-фрейм. Годовой план со скидкой ловит пиковые месяцы | в момент |
| **Winback** | Отменил 30+ дней назад | Возврат возможен при новой ценности («что нового») + одноразовый сильный оффер. Раньше 30д - раздражение, позже 90д - мёртво | 30-90д |

## 2. Иерархия офферов (что дарить, в порядке предпочтения)

1. **Юниты продукта** (токены/кредиты/место) - себестоимость < воспринимаемой
   ценности, не режет MRR, приучает пользоваться. Первый выбор для activation.
2. **Время** (продление триала) - нулевая себестоимость, конвертит
   «недорешивших». Первый выбор для trial conversion.
3. **Пауза подписки** - сохраняет отношения и данные, MRR вернётся. Первый
   выбор для save.
4. **Кредит на баланс $** - мягче скидки (одноразовый), для дуннинга как
   «извинение» и для save как жест.
5. **Скидка %** - РЕЖЕТ MRR и приучает ждать скидок. Только: (а) upgrade на
   годовой, (б) последний шаг save, (в) winback. Payback-правило: стоимость
   оффера должна отбиваться < 3 месяцев удержанного MRR.

Экономика: cost_estimate честный (купон = цена x % x месяцы; юниты = цена/лимит
x количество). Монетарные офферы - лимит 1/30д; немонетарные - до 2/30д.

## 3. Копирайт по типам (психология каждого письма)

- **Activation**: конкретное следующее действие + время («первый X за N минут»),
  социальное доказательство («большинство начинает с...»), бонус как повод.
  НЕ рассказывать о фичах - вести за руку к первой ценности.
- **Trial**: loss aversion - что юзер ПОТЕРЯЕТ (сделанную работу, данные,
  настройки). Дедлайн явный. Продление - как забота, не как отчаяние.
- **Dunning**: успокоить («это карта, не вы»), работа сохранна, действие 30
  секунд, ретраи автоматические. Эскалация мягкая: напоминание -> срочность
  последнего письма («доступ приостановится»), но без угроз.
- **Save**: признать право уйти, предложить паузу ДО скидки, показать
  сделанное юзером (инвестиция = якорь), новое в продукте.
- **Upgrade**: комплимент power-юзеру («вы в топе»), математика выгоды
  (за юнит дешевле), годовой план для пиковых нагрузок.
- Универсально: тема < 60 знаков, тело 1-3 предложения, один CTA, без
  капса/эмодзи/фальшивой срочности, писать от бренда КЛИЕНТА его юзерам.

## 4. Типы бизнесов и адаптация

| Тип | Юнит ценности | Особенности генерации |
|---|---|---|
| **Usage-based / credits** (API, генераторы) | токены/кредиты/минуты | Бонус-юниты - главный рычаг везде; upgrade через цену юнита |
| **B2B seats** (командные SaaS) | места/проекты | Юниты дарить нельзя (места = деньги напрямую) - дарить время и функции (feature unlock); activation = пригласить команду (aha-момент - коллаборация); тон формальнее |
| **Prosumer подписка** (фитнес, обучение) | сессии/планы | Streak/привычка в activation; пауза критична (сезонность); скидки работают, но режут и так низкий чек - лучше контент-анлоки |
| **Транзакционный SaaS** (бронирования, доки) | документы/брони | Ценность = завершённая транзакция; activation до первой транзакции - всё |

Сигналы типа: есть client_api + юниты -> usage-based; юнит "seats/мест" ->
B2B; низкий чек (<$15) + b2c-словарь -> prosumer.

## 5. Каркас цепочек (структура фиксирована платформой)

K1 activation: email(0ч, убрать трение) -> offer(бонус-юниты) -> email(48ч,
простейший путь). K2 trial: email(T-3, loss-frame) -> offer(продление) ->
email(+24ч, «добавили время»). K3 dunning: inapp(0ч) -> email(0ч, успокоить)
-> email(24ч, напомнить) -> email(72ч, последний звонок). K4 save:
offer(пауза) -> email(0ч, пауза вместо отмены) -> email(72ч, сделанное+новое).
K5 upgrade: email(0ч, математика) -> offer(годовой/скидка) -> email(48ч, оффер
словами). Роли офферов в каркасе: K1<-activation, K2<-conversion, K4<-save,
K5<-upgrade; dunning-кредит - вне каркаса (ручная выдача из /users).

## 6. Жёсткие ограничители (зашиты в код, промпт их только знает)

- percent_off <= max_discount_pct клиента; потолок 0 = никакой монетарщины.
- Схемы исполнителей (compose.EXECUTOR_SCHEMAS) - неизвестные поля отбрасываются.
- Холдаут 10% всегда; гигиена: monetary cap 14д, лимит выдач 30д,
  high_p_convert не получает скидок.
- LLM ПРЕДЛАГАЕТ - код валидирует и исполняет. Любой невалидный оффер/текст
  молча заменяется детерминированной базой.
