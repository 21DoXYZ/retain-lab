# ТЗ: Revenue Autopilot — SaaS-пресет retention-CRM

**MVP на Hub Content (видеогенерация, подписка + токены)**
Версия: 1.0 · Дата: 2026-08-03 · Статус: черновик для команды разработки
База: текущая retention-CRM (demo.21do.xyz) — переиспользуем ядро, выключаем казино-модули, достраиваем дельту.

---

## 0. Цель и контекст

Hub Content — SaaS видеогенерации: юзер идёт по флоу «идея → интеграция продукта → готовое видео», платит подписку, расходует токены (мы перепродаём токены генерации). Проблема: с юзерами никто не коммуницирует. Регистрации без активации, триалы без оплаты, подписчики без апгрейда, отмены без winback — всё молча утекает.

Продукт: **автоматическая revenue-машина** поверх SaaS — скоринг каждого юзера → рекомендованное действие + оффер → автоцепочка по каналам (email / Telegram / WhatsApp / AI-звонок / in-app) → замер инкремента против контрольной группы.

Стратегическая цель: Hub Content = дизайн-партнёр №1 и dogfood. По результатам MVP продукт пакуется как «SaaS-пресет» CRM и продаётся другим SaaS-стартапам без revenue-команды (модель: база $99–199/мес + 10–20% от доказанного инкремента).

**Ключевая идея:** токены = бонусная валюта с почти нулевой маржинальной стоимостью (аналог фриспинов). Вся бонус-экономика казино, включая causal-замер эффекта, переносится 1:1.

## 1. Маппинг сущностей: казино → SaaS

| Казино-CRM (сейчас) | SaaS-пресет (Hub Content) |
|---|---|
| Игрок | Юзер (user) |
| Депозит / FTD | Оплата подписки / первая оплата (first payment) |
| Redeposit | Renewal, докупка токенов (top-up) |
| GGR / NET | MRR / Net Revenue |
| Ставка / игровая сессия | Генерация видео / продуктовая сессия |
| Бонус (фриспины, мин-деп, вейджер) | Оффер (токены, скидка, extended trial, upgrade trial) |
| Кит / VIP-тир | Power user (высокий token burn), кандидат на Pro/Agency/Annual |
| Риск ухода (churn) | Риск отмены / неренewала / trial expiry |
| Колл-центр / очередь оператора | Автоцепочки; для горячих — AI-звонок (Retivo) или звонок фаундера |
| Аффилиаты | Источники привлечения (utm/канал) — упрощённо |

Стадии Пульта переименовываются, логика сохраняется:

| Было | Стало | Определение (MVP-правила) |
|---|---|---|
| CONVERT (первый деп) | **ACTIVATE** | Зарегистрирован, 0 сгенерированных видео за 48ч |
| NUDGE (2-й деп) | **CONVERT** | Активирован/trial, нет оплаты; trial истекает ≤3 дней |
| NURTURE (растить) | **UPGRADE** | Платящий, burn rate ≥80% лимита плана ИЛИ 2 мес подряд ≥60% |
| SAVE (удержать) | **SAVE** | Платящий, активность упала (правило: генерил ≥3 дней/нед → 0 за 7 дней) ИЛИ отменил автопродление |
| WINBACK | **WINBACK** | Отменён/expired ≥30 дней |
| MONITOR | **MONITOR** | Всё остальное |

## 2. Архитектура MVP: переиспользуем / выключаем / строим

**Переиспользуем без изменений (ядро):** движок цепочек (триггер → шаги → условия → ожидания) с контрольной группой; сегменты-конструктор; RFM/когорты/воронка; каталог офферов (механика каталога бонусов); скоринг-пайплайн (ночной пересчёт); карточка юзера; ролевая модель; ключи интеграции (bearer + IP-allowlist); causal-замер эффекта офферов (propensity matching + holdout).

**Выключаем (модульность):** анализ звонков колл-центра, Пульт-очередь операторов (в MVP нет живых операторов), аффилиат-P&L (оставляем срез по utm_source), GGR-экраны, VIP-планировщик звонков, «Играют сейчас» (v2: «Генерят сейчас»).

**Строим (дельта MVP):**
1. **Ingestion-слой SaaS**: Stripe/Paddle webhooks + JS/REST SDK продуктовых событий (§3).
2. **Каналы**: email-провайдер (Resend/Postmark/SES — выбрать по deliverability и цене), Telegram-бот, in-app виджет. WhatsApp — уже есть (DecisionTelecom). AI-звонки — интеграция Retivo (фаза 2).
3. **Оффер-экзекьюторы**: начисление токенов через API Hub Content; генерация купона Stripe (percent_off / amount_off, TTL); продление trial через API.
4. **Геймификация-модуль** (§6): колесо, стрики, миссии, уровни.
5. **Contact capture + consent** (§7): TG request_contact, OTP-верификация, consent-флаги, гео-маршрутизация каналов.
6. **Uplift-отчёт** (§9): «инкремент против holdout» в деньгах — основа rev-share биллинга.

## 3. Модель данных и ingestion

### 3.1 Таблицы (замена казино-схемы users/money_transactions/game_sessions/game_transactions)

**users**: user_id, email, phone, phone_verified (bool), tg_chat_id, tg_username, country (ISO), locale, created_at, utm_source/medium/campaign, consent_email, consent_messenger, consent_calls (bool + timestamp каждый), current_plan, plan_started_at, trial_ends_at, subscription_status (trialing/active/past_due/canceled/expired), tokens_balance, tokens_limit_month.

**payments** (из Stripe/Paddle webhooks): payment_id, user_id, type (subscription/topup), plan, amount, currency, status, mrr_delta, created_at, invoice_id.

**usage_events** (из SDK): event_id, user_id, event_type, props (JSON), created_at. Минимальный словарь событий MVP:
- `signup`, `onboarding_step` (props.step), `project_created`
- `generation_started`, `generation_completed` (props: tokens_spent, duration, template), `generation_failed`
- `video_downloaded`, `video_shared`
- `paywall_viewed` (props.plan), `checkout_started`, `checkout_abandoned`
- `plan_page_viewed`, `cancel_flow_started`, `cancel_reason` (props.reason)
- `tokens_low` (баланс <15% лимита), `tokens_exhausted`
- `login`, `session_start`

**offers_issued**: offer_id, user_id, campaign_id, offer_type, params (JSON), cost_estimate, issued_at, redeemed_at, expires_at, holdout_flag (bool — юзер в контрольной группе, оффер НЕ выдан).

### 3.2 Stripe webhooks (обязательный набор)
`customer.created`, `customer.subscription.created/updated/deleted`, `invoice.paid`, `invoice.payment_failed`, `charge.refunded`, `checkout.session.completed`, `checkout.session.expired`.

`invoice.payment_failed` → отдельная стадия **DUNNING** (involuntary churn): цепочка «обнови карту» — самый дешёвый recovered revenue, включить в MVP.

### 3.3 SDK
REST endpoint `POST /api/v1/events` (bearer-ключ — механика ключей уже есть) + лёгкий JS-сниппет-обёртка. Батчинг, идемпотентность по event_id.

## 4. Скоринг (MVP: эвристики → v2: ML)

MVP сознательно стартует на прозрачных правилах (данных для ML мало), интерфейсы — те же, что у ML-скоринга, чтобы v2 подменил реализацию без изменения контрактов.

- **P(convert)** — скор 0–100: активация (сгенерил ≥1 видео +30; ≥3 +20), просмотр paywall (+15), checkout_started (+25), давность последней сессии (−5/день), источник (по конверсии utm-когорты).
- **P(churn)** — для платящих: падение частоты генераций WoW (−40%→+30), cancel_flow_started (+40), tokens не расходуются 14 дней (+20), past_due (+30).
- **LTV-прогноз** — v1: средний LTV по когорте плана × поправка на burn rate. Кривая D1→D120 из VIP-радара переиспользуется на данных payments.
- **Power-скор (апгрейд)**: burn rate ≥80% (+40), генерации в ≥15 дней месяца (+20), team-фичи/просмотр Pro-страницы (+20).

Выход скоринга — как в казино: user_id, стадия, скоры, **рекомендованное действие + рекомендованный оффер из каталога + канал + когда**.

## 5. Каталог офферов

Каждый оффер: type, params, стоимость (COGS-оценка), лимиты выдачи (max/юзер/период), TTL, условия доступности, исполнитель (API-вызов).

| # | Оффер | Params | COGS | Исполнитель |
|---|---|---|---|---|
| O1 | Бонус-токены | amount (50/100/300), expires_days | ~себестоимость генерации ≈ низкая | API Hub Content: credit tokens |
| O2 | Скидка на подписку | percent (10–40%), months (1–3), plan | % MRR | Stripe coupon + checkout link |
| O3 | Extended trial | +days (3/7) | ~0 | API: trial_ends_at += |
| O4 | Upgrade trial | plan Pro, days (7) | ~0 | API: временный план |
| O5 | Priority render queue | days | ~0 | флаг в рендер-очереди |
| O6 | Персональный шаблон под нишу юзера | template_id | разовая работа | контент-команда/автоген |
| O7 | Annual deal | скидка % при переходе на годовой | дисконт | Stripe checkout link |

Правила гигиены (из казино-опыта, обязательны): оффер не выдаётся, если P(convert) уже высокий (антиканнибализация — «не дарить тем, кто и так купит»); лимит частоты (не чаще 1 монетарного оффера / 14 дней / юзер); каждый оффер логируется в offers_issued с holdout.

## 6. Геймификация (полный список активностей)

### G1. Welcome-миссии (онбординг-квест)
Чек-лист в UI + прогресс-бар: создай проект (+20 ток.) → сгенерируй первое видео (+50) → скачай/поделись (+30) → подключи Telegram (+100) → заполни профиль/нишу (+30). Цель: активация + сбор данных. Триггеры шлют цепочка-напоминания, если шаг не сделан за 48ч.

### G2. Колесо фортуны (Spin the Wheel)
Сектора: токены (50/100/300), скидка 10–30%, extended trial, priority render, «пусто» (редко). Веса секторов конфигурируются; дорогие сектора — низкий вес. Спин доступен по событиям: завершение welcome-миссий; последний день триала (retention-спин); подтверждение телефона; 1 спин/мес для активных подписчиков. Анти-абьюз: 1 аккаунт = лимиты по device/fingerprint + verified phone для монетарных призов.

### G3. Стрик генераций
N дней подряд с ≥1 генерацией → множитель бонус-токенов (3 дня ×1.2, 7 дней ×1.5, drop при пропуске). Пуш «стрик сгорает» — вечером в TG. Цель: привычка → удержание.

### G4. Уровни (тиры юзера)
Bronze/Silver/Gold/Creator по кумулятивным генерациям + оплатам. Перки: ранний доступ к фичам, priority render, скидка на топ-ап. Тир виден в UI и используется скорингом (аналог VIP-тиров).

### G5. Referral
Пригласи → оба получают токены (реферал — после первой генерации, не за регистрацию — анти-фрод). В MVP: простая ссылка + счётчик.

### G6. Low-balance драматургия
При балансе <15%: виджет «осталось ~N видео» + оффер топ-ап/апгрейд (O7 если power-скор высокий). Это главный момент апселла — трактовать как событие первого класса.

### G7. Каникулы вместо отмены (save-механика)
В cancel-flow: «заморозить подписку на 1 мес» / «даунгрейд» / O2-скидка — до подтверждения отмены. Классика SAVE из казино: оффер ДО ухода в 3–5× дешевле winback после.

MVP-скоуп геймификации: **G1, G2, G6, G7** (максимальный эффект на конверсию/удержание). G3–G5 — фаза 2.

## 7. Сбор контактов и верификация (email-only → мультиканал)

Принцип: телефон НЕ спрашиваем на регистрации. Собираем после активации в моменты пользы, платим токенами.

| # | Механика | Что получаем | Стоимость | Когда предлагаем |
|---|---|---|---|---|
| C1 | **Telegram-бот**: «уведомления о готовности видео + 100 токенов». Кнопка `request_contact` в боте | tg_chat_id + **верифицированный телефон** (верифицирует сам Telegram) | $0 | После первой генерации (пока рендерится — идеальный момент) |
| C2 | **WhatsApp-доставка видео**: «получить видео в WhatsApp» → номер → OTP (DecisionTelecom) | phone_verified + WA-канал | ~$0.01–0.05/OTP | Для гео, где TG слаб (LatAm и др.) — выбор по country |
| C3 | **Колесо за телефон**: спин G2 доступен после подтверждения номера | phone_verified | OTP | Триал день −1, если C1/C2 не сработали |
| C4 | **Онбординг-звонок**: для P(convert) ≥ порога — «15 мин, настроим пайплайн под твою нишу» | phone + **явный consent_calls** | 0 | Пейволл/checkout_abandoned у горячих |

Запрещено: использовать номер, собранный для 2FA/безопасности, в маркетинговых касаниях (GDPR purpose limitation).

**Consent-модель:** отдельные флаги consent_email (по умолчанию при регистрации, с unsubscribe), consent_messenger (при подключении канала), consent_calls (ТОЛЬКО явный чекбокс, отдельно от ToS, с timestamp и текстом согласия). 

**Гео-маршрутизация каналов (в движке цепочек):**
- US: email + in-app; звонки/SMS только при явном opt-in (TCPA: риск $500–1500/звонок); AI-voice юзерам US — не использовать в MVP.
- EU/UK: email (double opt-in желателен) + TG/WA при подключении; звонки по consent_calls.
- CIS/TR/LatAm/Asia: полный стек, включая AI-звонки по consent_calls.
- Канал выбирается: consent → доступность канала у юзера → приоритет (TG/WA > email по open rate) → гео-правило.

KPI сбора: contact capture rate ≥35% активированных юзеров к 60-му дню; call-consent ≥10% горячих.

## 8. Кампании MVP (5 цепочек, все с контрольной группой 10%)

| # | Кампания | Триггер | Шаги (укорочено) | Метрика успеха |
|---|---|---|---|---|
| K1 | Активация | signup, через 48ч 0 генераций | Email «первое видео за 3 мин» (шаблон под utm-нишу) → +48ч: O1 50 токенов → +72ч: TG/WA если есть | activation rate |
| K2 | Trial→Paid | trial_ends_at −3 дня, нет оплаты | День −3: email кейс+ценность → День −1: спин колеса (сегмент P(convert) низкий/средний; высоким — ничего, антиканнибализация) → День 0: O3 +3 дня ИЛИ O2 −20% | trial→paid CR |
| K3 | Dunning | invoice.payment_failed | Сразу: email+TG «обнови карту» → +24ч: retry-ссылка → +72ч: O3-жест | recovered MRR |
| K4 | Save | SAVE-стадия (активность ↓ или cancel_flow) | In-app каникулы/даунгрейд (G7) → email «что нового + твоя статистика» → горячим: слот на звонок (C4) | отток платящих ↓ |
| K5 | Upgrade | UPGRADE-стадия / tokens_low у power | In-app G6 → email «на Pro твой токен дешевле на N%» → O7 annual при power-скоре топ | expansion MRR |

Каждая кампания: holdout 10% (не получает касаний), атрибуция конверсии в окне (K1/K2 — 7 дней, K3 — 7, K4/K5 — 30), отчёт uplift.

## 9. Causal-замер и uplift-отчёт (основа rev-share)

Переиспользуем движок «эффект бонуса» из казино. Для каждой кампании считаем и показываем на одном экране:
- Конверсия target vs holdout, абсолютный uplift, CI.
- **Инкрементальная выручка**: (CR_target − CR_holdout) × N_target × средний чек/LTV-окно.
- Стоимость офферов (токены по COGS, скидки по дисконту MRR).
- ROI кампании и суммарно «сколько денег машина принесла за месяц: $X».

Этот экран = биллинг-основа rev-share (10–20% от инкремента) и главный слайд продаж пресета другим SaaS. Требование: методика фиксируется в «Формулах расчётов» (экран уже есть), без права тихой правки задним числом.

## 10. Экраны админки MVP

1. **Обзор** — MRR, активные, триалы, конверсия воронки reg→activate→trial→paid, «машина принесла $X» (из §9).
2. **Пульт-SaaS** — список юзеров по стадиям (ACTIVATE/CONVERT/UPGRADE/SAVE/WINBACK/DUNNING) с ценностью на кону, скором, рекомендованным действием.
3. **Карточка юзера** — таймлайн событий, платежи, токены, каналы+consent, выданные офферы, скоры, рекомендация.
4. **Кампании** — конструктор цепочек (существующий) + статус/uplift по каждой.
5. **Каталог офферов** — CRUD + лимиты + COGS.
6. **Отчёт uplift** (§9).
Существующие RFM/когорты/воронка — включены как есть на новых данных.

## 11. Роадмап

**Фаза 0 — MVP (цель: 3–4 недели):** ingestion (§3), стадии+эвристический скоринг (§4), офферы O1–O4 (§5), геймификация G1/G2/G6/G7, contact capture C1+C2 (§7), каналы email+TG+in-app, кампании K1–K5 с holdout, uplift-отчёт, экраны §10.

**Фаза 1 (+4–6 недель):** WhatsApp-цепочки, C3/C4, G3–G5, «Генерят сейчас» real-time, ML-скоринг на накопленных данных, cancel-reason аналитика.

**Фаза 2:** AI-звонки Retivo (по consent_calls, вне US), Annual/expansion-плейбуки, мультитенантность пресета (onboarding второго SaaS-клиента: подключение = Stripe key + SDK-сниппет + выбор офферов ≤1 дня).

**Вне скоупа MVP:** push/in-app-нотификации мобильные, A/B текстов (только A/B офферов через holdout), интеграции кроме Stripe.

## 12. KPI успеха MVP (60 дней на Hub Content)

- Trial→Paid: uplift ≥ +15% отн. к holdout.
- Activation rate: +10 п.п.
- Recovered MRR (dunning): ≥50% failed-инвойсов.
- Contact capture: ≥35% активированных.
- Отчёт «$X инкремента» работает и сходится с ручной проверкой.
- Ни одного касания без consent-флага (аудит-лог).

## 13. Открытые вопросы
1. Биллинг Hub Content — Stripe или Paddle? (влияет на §3.2 и купоны)
2. API начисления токенов — есть ли endpoint или делаем?
3. Гео-структура текущей базы юзеров (решает приоритет C1 vs C2 и «белость» AI-звонков).
4. Цены/лимиты планов — нужны для порогов burn rate и экономики офферов.
5. Кто владелец email-домена рассылок (deliverability: отдельный поддомен, прогрев).
