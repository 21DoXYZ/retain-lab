# 00 — Контекст проекта: Revenue Autopilot (Hub Content + SaaS-пресет)

*Главный документ базы знаний. Прочитай первым. Версия 1.0 · 2026-08-03*

---

## 1. Что это за проект

**Revenue Autopilot** — автоматическая revenue-машина для SaaS без revenue-команды: ML-скоринг каждого юзера → стадия жизненного цикла → рекомендованное действие + оффер → автоцепочка касаний по каналам → замер инкремента против контрольной группы в долларах.

**Первый клиент и полигон — Hub Content**: SaaS видеогенерации (флоу «идея → интеграция продукта → готовое видео»), модель: подписка + токены (перепродажа токенов генерации). Биллинг предположительно Stripe (уточняется). Боль: с юзерами никто не коммуницирует — регистрации без активации, триалы без оплаты, тихие смерти подписок при фейле карты, отмены без winback. Есть только email-канал.

**Стратегия**: dogfood на Hub Content → кейс с цифрами инкремента → продажа пресета другим micro-SaaS/AI-тулам (ЛПР — фаундеры; модель: база $99–199/мес + 10–20% от инкремента, доказанного контрольной группой).

## 2. Откуда продукт: что уже построено (родительская платформа)

Команда 2pizza.team построила **retention-CRM для онлайн-казино** (рабочее демо ~40 экранов): SPA + REST `/api/v1/*`, витрины ClickHouse, 3 локали (RU/EN/TR, ~3069 ключей i18n), 10 ролей.

Ключевые работающие модули родительской платформы:
- **Скоринг-пайплайн**: LTV-прогноз (кривая D1→D120), риск оттока, перспективность; ночной пересчёт; выход = «кому, когда, какой оффер».
- **Пульт**: очередь «задача × ценность на кону» по стадиям (SAVE/NURTURE/WINBACK/NUDGE/CONVERT/MONITOR).
- **Движок цепочек**: триггер → шаги → условия → контрольная группа; шаблоны сообщений; версии.
- **Causal-замер эффекта бонусов** (propensity matching, «сырая разница — обманчиво») — главный дифференциатор.
- **Каталог бонусов/офферов** с лимитами и подбором по юзеру.
- **Аналитика**: RFM, когорты, воронки, архетипы, конструктор отчётов.
- **Карточка юзера** с рекомендованным действием и оффер-воркфлоу.
- **Анализ звонков колл-центра** (AI-скоринг 100% звонков) — в SaaS-версии выключен, это отдельный модуль/апсел.
- **Каналы**: телефония, SMS/WhatsApp/Viber через DecisionTelecom (CPaaS), партнёрство по AI-звонкам с вендором Retivo.

Ребилд казино→SaaS = **форк с feature-флагами** (казино-модули выключаются, не удаляются; терминология через i18n). Оценка: ~60% переносится как есть, MVP за 3–4 недели.

## 3. Ключевые решения (зафиксировано)

1. **Токены = бонусная валюта** (себестоимость ~0, аналог фриспинов) — ядро оффер-экономики.
2. **7 стадий юзера**: ACTIVATE / CONVERT / UPGRADE / SAVE / DUNNING / WINBACK / MONITOR (правила — в ТЗ §1).
3. **Каждая кампания с контрольной группой 10%** — отчёт в долларах инкремента; это же основа rev-share биллинга.
4. **Антиканнибализация**: офферы не выдаются юзерам с высоким P(convert); ≤1 монетарный оффер / 14 дней.
5. **Сбор контактов после активации, не на регистрации**: TG-бот «видео готово» + токены → верифицированный номер в 1 тап бесплатно; WhatsApp+OTP для гео без TG; телефон за спин колеса; онбординг-звонок для горячих.
6. **Consent-модель**: отдельные флаги email/messenger/calls с timestamp; US — без звонков/SMS (TCPA, иски $500–1500/звонок); AI-звонки — только вне US и по явному согласию (фаза 2, Retivo).
7. **MVP-скоринг = прозрачные эвристики** с контрактами под будущий ML.
8. **Геймификация MVP**: welcome-миссии, колесо фортуны, low-balance момент, «каникулы вместо отмены». Фаза 2: стрики, уровни, referral.
9. **MVP-кампании (5)**: активация (48ч без видео) · дожим триала (−3 дня) · dunning (payment_failed) · спасение (остывание/cancel-flow) · апгрейд (burn ≥80%).

## 4. Цели MVP (60 дней на Hub Content)

Trial→Paid +15% против контрольной группы · активация +10 п.п. · dunning recovery ≥50% · ≥35% активных юзеров с мессенджер-каналом · отчёт «машина принесла $X», сверяемый вручную · ноль касаний без consent.

## 7. Глоссарий

**Burn rate** — доля израсходованных токенов от лимита плана. **Dunning** — реанимация упавших платежей. **Holdout / контрольная группа** — 10% сегмента без касаний для честного замера. **Инкремент** — разница конверсии target vs holdout × чек. **NBA (next-best-action)** — рекомендованное действие по юзеру. **Оффер** — стимул из каталога (токены/скидка/trial). **Пресет** — конфигурация платформы под вертикаль (казино / SaaS / далее брокеры и др.). **Стадия** — положение юзера в жизненном цикле (7 стадий).

## 8. Смежный контекст (родительская стратегия 2pizza, для справки)

Casino-CRM остаётся основным бизнесом (клиенты-казино, эксперт Василий по ретеншену). Проведён deep research рынков экспансии; приоритеты: forex/CFD-брокеры (~0% ре-билда, чек $2–6k/мес), collections Казахстан (регуляторный спрос), COD-товарка и EdTech (быстрые циклы), регулируемый беттинг Бразилии. Revenue Autopilot / SaaS-пресет — отдельная волна этой стратегии с самым дешёвым тестом (первый клиент — свой продукт). Детали — в проекте «Casino», сюда не дублируются.
