# Predictions Delivery

## Обзор

Предсказания пересчитываются **ежедневно** (ночной batch-скоринг всех моделей) и
доставляются тремя каналами: дашборд (операционка), callback-сигналы (push в вашу
систему), выгрузки (XLSX для колл-центра). Витрины скоров доступны и напрямую для BI.

| Канал | Кому | Статус |
|---|---|---|
| Дашборд Sellrise | retention-команде, VIP-менеджерам, руководителям | ✅ работает |
| Callback-сигналы | вашему бэкенду/CRM (авто-триггеры бонусов) | 🟡 включается после согласования формата и обмена токенами |
| Выгрузки XLSX | колл-центру | ✅ работает |
| Витрины скоров (BI) | аналитикам | ✅ работает |

## Витрины предсказаний

Каждая модель ежедневно перезаписывает свою витрину скоров. Ключ везде —
`casino_player_id`. Полный справочник витрин и колонок (состав предиктивного слоя)
передаётся отдельным документом на этапе интеграции.

## Канал 1 — дашборд Sellrise

Скоры выведены туда, где принимается решение:

- **Карточка игрока** — вся история + прогнозы (LTV-полоса, риск, next-best-action).
- **Пул / Пульт / Играют сейчас** — очереди работы с назначением оператору в один клик.
- **Моя очередь** — задачи оператора; исход звонка двигает статус, реакция игрока
  (депозит/игра ≤7 дней) фиксируется автоматически.
- **/ltv, /actions** — ранжирование базы по ценности и списки действий.

Доступ — по ролям ([Authentication & Access](authentication-and-access.md)).
VIP-скоры в карточке и сигналах — ближайший релиз (витрины уже наполняются).

## Канал 2 — callback-сигналы (мы → вы)

После ночного скоринга мы POST'им батчи сигналов на ваш эндпоинт:

```
POST https://<ваш-домен>/api/sellrise/signals
GET  https://<ваш-домен>/api/sellrise/health    (проверка перед отправкой)
Authorization: Bearer <SELLRISE_CALLBACK_TOKEN>
```

Конверт:

```json
{
  "model_version": "2026-06-20",
  "scored_at": "2026-06-20 14:37:00",
  "signals": [
    {
      "casino_player_id": 40,
      "pred_ltv_d90": 12345.60,
      "p_churn_30d": 0.87,
      "p_next_deposit": 0.42,
      "ltv_tier": "D",
      "recommended_action": "SAVE",
      "recommended_bonus": "cashback",
      "priority": 9876
    }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `pred_ltv_d90` | number | прогноз депозитов на 90 дней |
| `p_churn_30d` | 0..1 / null | вероятность оттока за 30 дней |
| `p_next_deposit` | 0..1 / null | вероятность следующего депозита |
| `ltv_tier` | `A`/`B`/`C`/`D` | ценностный тир (D — «кит») |
| `recommended_action` | enum | `CONVERT` · `NUDGE` · `SAVE` · `WINBACK` · `NURTURE` · `MONITOR` |
| `recommended_bonus` | enum | `first_deposit_bonus` · `second_deposit_reload` · `reload_cashback` · `vip_offer` · `freespins` · `other` |
| `priority` | int | больше = важнее |

Все значения — стабильные машиночитаемые ASCII-коды, можно матчить программно.

**Доставка:** at-least-once, батчами; идемпотентность по `casino_player_id` в рамках
одного `scored_at` — берите последнюю запись по времени.

## Канал 3 — выгрузки колл-центру

Ежедневные сегментные списки со скорами, приоритетом и рекомендацией:
at-risk · dormant · churned · never-deposited. XLSX, выгружаются из дашборда;
состав колонок настраивается под скрипты колл-центра.

## Мониторинг и статус моделей

- **Свежесть:** дашборд показывает cutoff данных; `scored_at`/`model_version` приходят
  в каждом батче сигналов.
- **Здоровье скоринга:** сервисный `GET /health` возвращает время и тайминги
  последнего прогона; повторный запуск скоринга защищён от параллельного выполнения.
- **Качество моделей:** метрики фиксируются в реестре при каждом переобучении
  (еженедельный цикл); деградация видна по сравнению версий.

## Ошибки и повторы (callback)

| Ситуация | Поведение |
|---|---|
| ваш эндпоинт недоступен | ретраи с экспоненциальной паузой, доставка at-least-once |
| частичная обработка батча | безопасно: записи идемпотентны в рамках `scored_at` |
| смена формата | версионируется полем `model_version`; изменения анонсируются заранее |
