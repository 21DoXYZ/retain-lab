# B2B Integration Architecture

## Схема интеграции

```
ваш бэкенд ──HTTP POST /ingest/events──┐
ваш бэкенд ──потоковый канал───────────┼─►      Sellrise
бэкфилл истории (Parquet/CSV дампы) ────┘   приём → обработка → ML-скоринг
                                                        │
                                       ┌────────────────┼────────────────┐
                                       ▼                ▼                ▼
                              дашборд Sellrise   callback-сигналы   выгрузки XLSX
                              (CRM-операционка)  POST на ваш API    (колл-центр)
```

Внутренняя обработка — «чёрный ящик»: оператор шлёт события/историю по интерфейсам
ниже и получает готовые предсказания. Состав моделей и предиктивного слоя — в
отдельной внутренней документации, передаётся по запросу.

## Точки интеграции

### 1. Аутентификация 🔐

Токены и доступы выдаются при подключении, по каналу отдельно от документации.
Детали — [Authentication & Access](authentication-and-access.md).

### 2. Загрузка данных 📤

| Канал | Что | Когда использовать |
|---|---|---|
| `POST /ingest/events` (HTTP) | события игроков поштучно или батчами до 1000 | старт интеграции, средние объёмы |
| Потоковый канал (Kafka-совместимый) | те же события потоком | большие объёмы, минимальная задержка |
| Дампы Parquet/CSV | исторический бэкфилл, разовые дозаливки | история до включения потока |

Один контракт события для обоих каналов — [Real-time Event Ingestion](realtime-event-ingestion.md).
8 типов событий: `user`, `bet`, `win`, `session_start`, `session_end`, `deposit`,
`withdrawal`, `bonus`.

### 3. Получение предсказаний 📊

| Канал | Формат | Режим |
|---|---|---|
| Дашборд Sellrise | карточка игрока, пул, пульт, live | интерактивно, RBAC-роли |
| Callback-сигналы | `POST` батчей JSON на ваш эндпоинт | push, ежедневно после скоринга |
| Выгрузки | XLSX-списки сегментов со скорами | ежедневно / по запросу |

Детали и формат сигнала — [Predictions Delivery](predictions-delivery.md).

### 4. Мониторинг 📈

- Свежесть данных и предсказаний видна в дашборде (метка cutoff).
- Здоровье скоринга — сервисный `GET /health` (время и тайминги последнего прогона).
- Метрики каждой модели фиксируются в реестре при каждом переобучении.

## Варианты интеграции

**Вариант A — HTTP push (рекомендуется для старта).** Ваш бэкенд шлёт события на наш
эндпоинт. Минимум инфраструктуры с вашей стороны: HTTP-клиент + ретраи + outbox.

**Вариант B — потоковый канал (Kafka-совместимый API).** Продюс напрямую в потоковый
приёмник (SASL_SSL). Для больших объёмов и когда у вас уже есть событийная шина.

**Вариант C — batch pull/дампы.** Если событийного потока нет: регулярные Parquet-дампы
в object storage или прямой pull из read-реплики вашей БД.
Детали — [Batch Data Ingestion](batch-data-ingestion.md).

## Итоговый поток

```
Ваша платформа → Аутентификация → Поток событий (+бэкфилл) → ML-скоринг →
→ Предсказания → Дашборд / Сигналы / Выгрузки → Действия retention-команды →
→ Реакция игрока возвращается событиями → цикл замыкается
```

**Частота пересчёта:** предсказания обновляются ежедневно (ночной скоринг);
переобучение моделей — еженедельно.

**Ключевое отличие от скоринг-вендоров:** предсказания приходят не «сырыми скорами в
API», а внутри готовой операционки — с назначениями, звонками, статусами и обратной
связью по каждому контакту. Слой действий уже построен.
