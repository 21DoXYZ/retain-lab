# Генератор постов для Telegram-канала — Промпт-инструкция

> **Тип:** Инструкция (Instruction)
> **Фаза:** 9 — Маркетинг
> **Цель:** По теме/идее Claude генерирует пост для Telegram-канала в одном из трёх форматов: short (инсайт), medium (кейс), long (туториал) — с хуком, телом, CTA и хештегами

---

## Философия этого документа

Этот файл — **готовый промпт для Claude AI**. Вы не пишете его сами — копируете и используете.

**Принцип работы:**
- Вы — архитектор и коммуникатор: знаете, ЧТО хотите рассказать
- Claude — исполнитель: упаковывает вашу идею в правильный формат поста
- Ваша задача — описать тему/инсайт и скопировать промпт

**Workflow:**
```
Вы → копируете промпт → загружаете в Claude AI (web)
       ↓
       прикрепляете тему/идею/тезис + желаемый формат (short/medium/long)
       ↓
Claude → генерирует пост по выбранной структуре
       ↓
Вы → получаете готовый пост → публикуете в канале
```

Промпт уже отлажен. Не нужно его улучшать с первого раза — просто используйте.

---

## Зачем нужен этот документ

Telegram-канал — это **глубокий контент** для лояльной аудитории. В отличие от Reels (охват) и YouTube (SEO), Telegram строит прямую связь с подписчиками.

Три формата покрывают все потребности:

| Формат | Длина | Время чтения | Цель |
|--------|-------|-------------|------|
| Short (инсайт) | 300-500 символов | 30 сек | Охват, шеры, быстрая ценность |
| Medium (кейс) | 800-1500 символов | 2-3 мин | Доверие, экспертность, вовлечение |
| Long (туториал) | 2000-3500 символов | 5-7 мин | Глубокая ценность, сохранения |

**Правило:** Каждый пост начинается с хука. Если первое предложение не цепляет — пост пролистают.

## Промпт для Claude

```
Ты — копирайтер для Telegram-канала AI-архитектора.

Твоя задача — сгенерировать пост для Telegram-канала 
по заданной теме в указанном формате.

## Три формата

### SHORT (инсайт) — 300-500 символов
Структура:
1. Хук (1 предложение — шокирующий факт или мысль)
2. Развитие (2-3 предложения — контекст и суть)
3. Вывод (1 предложение — ключевая мысль, которую запомнят)
4. CTA (1 строка — вопрос для обсуждения или призыв)

Тон: лаконичный, уверенный, как мысль вслух.
Форматирование: без заголовков, без списков. Сплошной текст 
с разделением на абзацы.

### MEDIUM (кейс) — 800-1500 символов
Структура:
1. Хук (1-2 предложения — результат или боль)
2. Контекст (2-3 предложения — что было, какая задача)
3. Процесс (3-5 предложений — что сделали, как решали)
4. Результат (2-3 предложения — конкретные цифры)
5. Урок (1-2 предложения — что вынести из этого)
6. CTA (1 строка)

Тон: разговорный, с деталями. Как рассказ другу.
Форматирование: эмодзи-маркеры (→, ·) допустимы, 
но не обязательны. Абзацы по 2-3 предложения.

### LONG (туториал) — 2000-3500 символов
Структура:
1. Хук (1-2 предложения — зачем это читать)
2. Контекст (2-3 предложения — для кого и зачем)
3. Пошаговая инструкция (5-7 шагов с описанием каждого)
4. Нюансы / ошибки (2-3 частые ошибки или подводные камни)
5. Итог (2-3 предложения — резюме)
6. CTA (1-2 строки)

Тон: обучающий, но не занудный. Практичный.
Форматирование: нумерованные шаги, **жирный** для ключевых слов,
`код` для технических терминов, абзацы через пустую строку.

## Правила для всех форматов:
1. Хук = первое предложение. Без приветствий, без «Друзья,».
2. Не используй кликбейт — только правдивые утверждения.
3. Конкретика > абстракции (цифры, сроки, суммы).
4. Один пост = одна мысль. Не распыляйся.
5. CTA — лёгкий (вопрос, реакция, «сохрани»). Не продажа.
6. Хештеги — 3-5 штук, в самом конце, через пробел.
7. Текст на русском, технические термины — как есть (API, Claude Code, MCP).

## [ВХОДНЫЕ ДАННЫЕ]

### Тема/идея поста:
[Опиши тему в 1-2 предложениях]

### Формат:
[short / medium / long]

### Контекст (если есть):
[Дополнительные детали, цифры, кейс]

### Для какой аудитории:
[предприниматели / разработчики / фрилансеры / все]
```

### MEDIUM (кейс)

```
Собрал SaaS-продукт за 7 дней. Вот как это 
было — день за днём.

Идея была простая: трекер задач для фрилансеров, 
который сам приоритизирует задачи через AI и присылает 
напоминания в Telegram. Существующие трекеры 
(Notion, Trello, Asana) не заточены под фрилансеров — 
они для команд. А фрилансеру нужна одна кнопка: 
«что делать первым».

День 1-2: Написал PROJECT_IDEA.md — описал проблему, 
аудиторию и 5 ключевых функций. Затем прогнал 
через Claude AI → получил полную спецификацию 
SPEC.md на 15 страниц.

День 3: Загрузил SPEC.md в Claude Code Setup Generator. 
Получил: CLAUDE.md, субагентов, правила, MCP-команды 
и финальный промпт.

День 4-5: Скопировал промпт в Claude Code → 
он создал все файлы, настроил Supabase (таблицы, RLS), 
собрал API и фронтенд. Я корректировал через 
естественный язык.

День 6: Подключил ЮKassa для платежей. Настроил 
вебхуки на VPS. Добавил Telegram-бота для уведомлений.

День 7: Деплой на Vercel (фронт) + Beget VPS (бэкенд). 
Тестирование. Фикс багов. Запуск.

Что получилось:
→ Авторизация (Supabase Auth)
→ Дашборд с AI-приоритизацией
→ Интеграция с Telegram
→ 3 тарифа (Free/Pro/Business)
→ Подключены платежи

Главный урок: спецификация решает всё. Без неё 
Claude Code «придумывает» решения. С ней — 
реализует точно то, что нужно. 80% работы — 
это документация. 20% — сборка. 
И именно этим AI-архитектор отличается от вайбкодера.

Если есть вопросы по конкретным этапам — 
пишите в комментариях, разберу подробнее.

#taskflow #saas #claudecode #specdriven #mvp
```

### LONG (туториал)

```
Как собрать SaaS-продукт за 7 дней — 
пошаговая инструкция

Неделю назад у меня была идея. Сегодня — 
работающий SaaS с авторизацией, AI-функциями, 
оплатами и Telegram-интеграцией. Расскажу 
пошагово, как это повторить.

Продукт: TaskFlow — AI-трекер задач для фрилансеров. 
Стек: Next.js + Supabase + Node.js на VPS. 
Инструмент: Claude Code (VS Code).

**Шаг 1: PROJECT_IDEA.md (2-3 часа)**

Самый важный шаг. Пишешь на человеческом языке:
— Какую проблему решаешь
— Для кого
— 3-7 ключевых функций
— Ограничения (бюджет, сроки)

Частая ошибка: писать 20+ функций. Это не MVP, 
это фантазия. Максимум 7 функций на старте.

**Шаг 2: SPEC.md через Claude AI (3-4 часа)**

Загружаешь PROJECT_IDEA.md в Claude AI (web) 
и просишь сгенерировать полную спецификацию. 
6 обязательных блоков:
1. User Stories
2. Data Model (готовый SQL)
3. API Endpoints
4. UI/UX (экраны, состояния)
5. Business Logic (правила, RLS)
6. Edge Cases

Спецификация пишется ДЛЯ AI-АГЕНТОВ, не для людей. 
Максимальная конкретность. Никаких TODO и placeholder'ов.

**Шаг 3: Claude Code Setup (1-2 часа)**

Загружаешь SPEC.md + Setup Generator → получаешь 
полный пакет: CLAUDE.md, субагенты, правила, 
MCP-команды, финальный промпт.

Подключаешь MCP-серверы:
— Supabase (доступ к БД)
— Context7 (актуальная документация)
— GitHub (версионирование)

**Шаг 4: Автономная сборка (1-2 дня)**

Копируешь финальный промпт в Claude Code → 
он создаёт структуру проекта, настраивает базу данных, 
пишет API и собирает фронтенд.

Субагенты работают по зонам:
`database-architect` → `backend-engineer` → 
`frontend-developer` → `qa-reviewer`

Твоя задача — корректировать через естественный язык:
«Перенеси кнопку в правый угол», 
«Добавь валидацию email», 
«Поменяй цвет на синий».

**Шаг 5: Интеграции (1 день)**

Подключаешь внешние сервисы:
— ЮKassa для платежей (регистрация → API → webhook)
— Telegram Bot API для уведомлений
— Email-рассылки (если нужны)

Всё через Node.js на VPS (не Edge Functions — 
у них таймаут 10 секунд).

**Шаг 6: Деплой (0.5 дня)**

— Vercel для фронтенда (Next.js)
— Beget VPS для бэкенда (Node.js + PM2 + Nginx)
— Supabase для БД (или self-hosted на VPS для РФ)

Настраиваешь домен, SSL, DNS.

**Шаг 7: Тестирование и запуск (0.5 дня)**

Тестируешь все сценарии:
— Регистрация → онбординг → создание задачи
— Оплата → активация тарифа
— Telegram-уведомления
— Мобильная версия

Фиксишь баги через Claude Code → git commit → деплой.

**Частые ошибки:**

1. Пропустить спецификацию и сразу кодить. 
   Результат: Claude Code «придумывает» решения, 
   которые не соответствуют задаче. Переделки 
   съедают больше времени, чем написание SPEC.md.

2. Не подключить MCP-серверы. Без Context7 
   Claude Code использует устаревшую документацию. 
   Без Supabase MCP — не видит структуру базы.

3. Делать «всё и сразу». MVP — это 3-5 функций. 
   Остальное — после первых пользователей.

**Итог:**

7 дней — это реальный срок для MVP. Но 80% этого 
времени — это документация и спецификация. 
Сам код пишет Claude Code. Ты — архитектор, 
он — строитель.

Если есть вопросы по конкретному этапу — 
пишите, разберу подробнее. Если хотите 
полный шаблон SPEC.md — напишите «спек» 
в комментариях.

#taskflow #saas #claudecode #specdriven #mvp #tutorial #ai
```

## Банк тем для постов

**AI-разработка:** Spec-driven vs вайбкодинг, промпты для Claude Code, MCP-серверы, субагенты, почему 80% времени — документация.

**Бизнес:** Выбор ниши, первые 10 клиентов, подписка vs проект, юридика в РФ (152-ФЗ, ЮKassa), расчёт ROI.

**Инструменты:** Стек и стоимость, Claude Code vs ChatGPT, Supabase, VPS в России, Context7.

**Личное:** Как не выгореть, мышление AI-архитектора, ошибки первого года, конкуренция.

## Чек-лист перед публикацией

- [ ] Хук — первое предложение цепляет
- [ ] Одна мысль на пост (не пытаюсь охватить всё)
- [ ] Конкретика: есть цифры, сроки, суммы
- [ ] CTA — лёгкое действие (вопрос, реакция, «сохрани»)
- [ ] Хештеги — 3-5 штук в конце
- [ ] Проверил на опечатки
- [ ] Формат текста — читается с телефона (короткие абзацы)
- [ ] Нет ссылок в начале поста (Telegram срезает охват)

---

*Ритм важнее качества на старте. Лучше публиковать 5 «нормальных» постов в неделю, чем 1 «идеальный». Идеальных не бывает — бывают опубликованные.*
