## Промпт для Claude AI

```
Ты — AI-архитектор, который рассчитывает стоимость разработки
программных проектов. Тебе дана спецификация (или описание) проекта.

## Твоя задача

Рассчитай стоимость проекта и выдай ДВА документа:

### Документ 1: Внутренняя смета (для себя)
Детальная разбивка по каждому модулю и компоненту:
- Модуль → компоненты
- Каждый компонент: время (в днях), сложность (1-5), стоимость
- Итоги по слоям (Frontend, Backend, Database, Infra)
- Общий итог с запасом на непредвиденные (15%)

### Документ 2: Клиентский саммари
Упрощённая таблица для клиента:
- Модуль → что получает клиент → стоимость
- Без технических деталей (никаких RLS, Edge Functions, миграций)
- С ценовым якорем (сравнение с рынком)

## Правила расчёта

### Дневная ставка (рынок РФ май 2026)
- Junior: 12 000-20 000 ₽/день (для проектов до 400K)
- Middle: 20 000-32 000 ₽/день (для проектов 400K-1M)
- Senior: 32 000-52 000 ₽/день (для проектов 1M+)

### Коэффициент сложности
| Сложность | Коэффициент | Примеры |
|-----------|:-----------:|---------|
| 1 (простая) | ×1.0 | CRUD, статические страницы, простые формы |
| 2 (средняя) | ×1.3 | Фильтры, поиск, drag-n-drop, файловый upload |
| 3 (сложная) | ×1.6 | Real-time, сложная бизнес-логика, платежи |
| 4 (высокая) | ×2.0 | AI-агенты, парсинг документов, оркестрация |
| 5 (экспертная) | ×2.5 | ML-пайплайны, высоконагруженные системы |

### Формула
```
Стоимость компонента = Базовые_дни × Коэффициент_сложности × Ставка_день
```

### Рыночная цена (для ценового якоря)
```
Рыночная цена = Наша цена × 2.5-3.5

## Быстрая оценка без SPEC.md

Если у тебя нет спецификации, а есть только устное описание от клиента, используй упрощённый промпт:

```
Клиент хочет: [ОПИСАНИЕ В 2-3 ПРЕДЛОЖЕНИЯХ]

Рассчитай грубую стоимость:
1. Разбей на модули (5-15 штук)
2. Каждый модуль: оценка в днях
3. Дневная ставка: 24 000 ₽ (middle AI-архитектор; уточни если другой уровень)
4. Итого = сумма дней × ставка × 1.15 (запас)
5. Рыночная цена = итого × 2.5-3

Выведи одну таблицу: Модуль | Дни | Стоимость
И итог + сравнение с рынком.
```

## Типичные ошибки при расчётах

### 1. Забыть про тестирование
Тестирование = 15-20% от общей суммы. Всегда включай.

### 2. Занизить сложность
Канбан — это не «просто список». Drag-n-drop, порядок сортировки,
сохранение состояния, оптимистичные обновления — сложность 2-3,
не 1.

### 3. Не учесть «невидимые» задачи
Что часто забывают:
- Состояния UI: loading, error, empty state
- Валидация форм
- Пагинация и бесконечный скролл
- Мобильная адаптация (responsive)
- Обработка edge cases (таймауты, ретраи)

### 4. Дать вилку вместо цифры
Клиенту: «600 000 ₽», не «500-700K ₽».
Себе: считай по верхней границе, озвучивай среднюю.

### 5. Не привязать к результату
**Плохо:** «Backend: 240 000 ₽»
**Хорошо:** «Вся серверная часть, чтобы приложение работало быстро и надёжно: 240 000 ₽»
