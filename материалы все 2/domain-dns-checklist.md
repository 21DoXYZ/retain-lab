## Философия этого документа

Этот файл — **проверочный список после действия Claude или вашего при подключении домена**. Вы не помните наизусть все DNS-записи и TTL — вы используете его как:

1. **Чек-лист валидации** — проверить, что все A/CNAME/MX/TXT записи на месте и корректны
2. **Reference для Claude** — загрузить в проект, чтобы Claude настроил DNS под ваш провайдер (Reg.ru, Cloudflare, Beget)
3. **Quick-reference** — когда "сайт не открывается", быстро найти типичный баг (TTL, propagation, не та A-запись)

**Принцип работы:**
- Вы — архитектор: купили домен, знаете, куда он должен вести
- Claude Code — исполнитель: знает, какие записи создать и как проверить через dig/nslookup
- Этот документ — общий язык между вами

**Как применять:**
```
Сценарий 1: Claude настраивает DNS
  Вы → "подключи домен taskflow.ru к серверу X" → Claude следует чек-листу

Сценарий 2: Вы настраиваете сами
  Вы → открываете файл → идёте пункт за пунктом в панели регистратора

Сценарий 3: Отладка
  Claude/Вы → сайт не открывается → сверяете с разделом troubleshooting → находите причину
```

## Шаг 1: Покупка домена

### Где покупать домен .ru / .com

| Регистратор | Домен .ru | Домен .com | Комментарий |
|-------------|-----------|------------|-------------|
| reg.ru | ~200 руб/год | ~900 руб/год | Популярный в РФ |
| beget.com | ~200 руб/год | ~900 руб/год | Удобно, если VPS тоже на Beget |
| nic.ru (RU-CENTER) | ~300 руб/год | ~1000 руб/год | Старейший регистратор |
| namecheap.com | — | ~$9/год | Для международных проектов |

### Рекомендация

Если VPS на Beget — покупать домен тоже на Beget. DNS-записи будут в одной панели, настройка проще.

### При покупке

- [ ] Выбрать домен (проверить доступность)
- [ ] Указать данные владельца (для .ru — паспортные данные)
- [ ] Включить защиту WHOIS (если доступна)
- [ ] Оплатить на 1-2 года
- [ ] Записать: домен, логин/пароль от панели регистратора

## Шаг 2: Настройка DNS-записей

### Основные типы DNS-записей

| Тип | Назначение | Пример значения |
|-----|-----------|-----------------|
| **A** | Указывает домен на IPv4-адрес сервера | `185.XXX.XXX.XXX` |
| **AAAA** | Указывает домен на IPv6-адрес | `2a00:xxxx::1` |
| **CNAME** | Псевдоним для другого домена | `taskflow.vercel.app` |
| **MX** | Почтовый сервер | `mx.yandex.net` |
| **TXT** | Текстовая запись (верификация, SPF) | `v=spf1 include:...` |
| **NS** | Серверы имён (nameservers) | `ns1.beget.com` |

### Сценарий A: Фронтенд на Vercel, бэкенд на VPS

```
taskflow.ru        → A     → 185.XXX.XXX.XXX  (VPS, если весь сайт на VPS)
                   → CNAME → cname.vercel-dns.com  (если фронт на Vercel)

api.taskflow.ru    → A     → 185.XXX.XXX.XXX  (VPS — бэкенд)
www.taskflow.ru    → CNAME → taskflow.ru
```

### Сценарий B: Всё на VPS

```
taskflow.ru        → A     → 185.XXX.XXX.XXX
www.taskflow.ru    → CNAME → taskflow.ru
api.taskflow.ru    → A     → 185.XXX.XXX.XXX
```

### Сценарий C: Всё на Vercel

```
taskflow.ru        → A     → 76.76.21.21  (Vercel)
www.taskflow.ru    → CNAME → cname.vercel-dns.com
```

## Шаг 3: Настройка DNS в панели Beget

### Если домен куплен на Beget

1. Войти в панель управления Beget (cp.beget.com)
2. Перейти в раздел **"Домены и DNS"** (или **"DNS"**)
3. Выбрать домен `taskflow.ru`
4. Перейти в **"Управление DNS-записями"**

### Добавление A-записи

| Поле | Значение |
|------|----------|
| Имя | `@` (или оставить пустым — означает сам домен) |
| Тип | A |
| Значение | `185.XXX.XXX.XXX` (IP вашего VPS) |
| TTL | 3600 (1 час) |

### Добавление CNAME для www

| Поле | Значение |
|------|----------|
| Имя | `www` |
| Тип | CNAME |
| Значение | `taskflow.ru` |
| TTL | 3600 |

### Добавление A-записи для поддомена API

| Поле | Значение |
|------|----------|
| Имя | `api` |
| Тип | A |
| Значение | `185.XXX.XXX.XXX` |
| TTL | 3600 |

### Если домен куплен не на Beget

Нужно сменить NS-серверы на серверы Beget:
```
ns1.beget.com
ns2.beget.com
```
Или настроить DNS у текущего регистратора (аналогично).

## Шаг 4: Ожидание пропагации DNS

- DNS-записи обновляются от 5 минут до 48 часов
- Обычно 15-30 минут для новых записей
- Проверить текущее состояние:

```bash
# Проверить A-запись
nslookup taskflow.ru
# или
dig taskflow.ru A +short

# Проверить CNAME
dig www.taskflow.ru CNAME +short

# Онлайн-сервисы для проверки
# https://www.whatsmydns.net/
# https://dnschecker.org/
```

## Шаг 5: SSL-сертификат (Let's Encrypt)

### На VPS (через Certbot)

```bash
# Установить Certbot (если не установлен)
sudo apt install -y certbot python3-certbot-nginx

# Получить сертификат
sudo certbot --nginx -d taskflow.ru -d www.taskflow.ru

# Для API-поддомена
sudo certbot --nginx -d api.taskflow.ru
```

### На Vercel

SSL подключается автоматически при добавлении домена:
1. Vercel Dashboard → Settings → Domains
2. Добавить `taskflow.ru`
3. Vercel покажет, какие DNS-записи нужно добавить
4. После пропагации DNS — SSL выдаётся автоматически

### Проверка SSL

```bash
# Проверить сертификат
curl -vI https://taskflow.ru 2>&1 | grep -E "SSL|subject|expire"

# Онлайн: https://www.ssllabs.com/ssltest/
```

## Шаг 6: Верификация

### Финальный чеклист

- [ ] `http://taskflow.ru` — редиректит на `https://taskflow.ru`
- [ ] `https://taskflow.ru` — открывается без ошибок сертификата
- [ ] `https://www.taskflow.ru` — работает (редирект или прямой доступ)
- [ ] `https://api.taskflow.ru` — если есть поддомен для API
- [ ] SSL-сертификат валиден (зелёный замок в браузере)
- [ ] Автообновление сертификата настроено:
  ```bash
  sudo certbot renew --dry-run
  ```

## Подключение домена к Vercel (подробно)

### Шаг 1: В панели Vercel

1. Открыть проект → Settings → Domains
2. Ввести `taskflow.ru` → Add
3. Vercel покажет инструкцию:
   - Для корневого домена: A-запись → `76.76.21.21`
   - Для www: CNAME → `cname.vercel-dns.com`

### Шаг 2: В панели регистратора (Beget)

Добавить записи, которые показал Vercel.

### Шаг 3: Дождаться верификации

Vercel автоматически проверит DNS и выдаст SSL. Статус виден в Dashboard.

## Настройка почты для домена (опционально)

Если нужна почта вида `info@taskflow.ru`:

### Яндекс.Почта для домена (бесплатно)

1. Подключить домен на connect.yandex.ru
2. Подтвердить владение (TXT-запись)
3. Добавить MX-записи:

| Тип | Значение | Приоритет |
|-----|----------|-----------|
| MX | `mx.yandex.net.` | 10 |

4. Добавить SPF (TXT-запись):
```
v=spf1 redirect=_spf.yandex.net
```

5. Добавить DKIM (TXT-запись — получить в Яндексе)

## Типичные ошибки

| Проблема | Причина | Решение |
|----------|---------|---------|
| ERR_NAME_NOT_RESOLVED | DNS ещё не пропагировался | Подождать 15-30 мин, проверить через dnschecker.org |
| ERR_SSL_PROTOCOL_ERROR | SSL не настроен | Запустить certbot или дождаться Vercel |
| Redirect loop | Двойной HTTPS-редирект (Nginx + Vercel/Cloudflare) | Убрать один из редиректов |
| CNAME для @ не работает | Корневой домен не поддерживает CNAME | Использовать A-запись для @ |
| Certbot: "Could not reach domain" | DNS не указывает на этот сервер | Проверить A-запись |
| Старый сайт показывается | Кеш DNS на локальной машине | `ipconfig /flushdns` (Windows) или ждать |
