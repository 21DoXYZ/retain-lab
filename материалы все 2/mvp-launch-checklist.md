# MVP Launch Checklist — Справочник

> **Тип:** Справочник (Reference)
> **Фаза:** 10 — Масштабирование
> **Цель:** Пошаговый чек-лист запуска MVP: от валидации идеи до первых 10 пользователей — с реалистичным таймлайном, инструментами на каждом этапе и критериями «сделано»

---

## Философия этого документа

Этот файл — **проверочный список после действия Claude или вашего на каждом этапе запуска MVP**. Вы не идёте по нему вслепую — вы используете его как:

1. **Чек-лист валидации** — после каждой фазы (валидация, сборка, лендинг, оплата, первые юзеры) свериться: сделано ли "сделано"
2. **Reference для Claude** — загрузить в проект, чтобы Claude Code вёл вас по фазам и напоминал, что критерий фазы 1 — подтверждённая боль, а не просто идея
3. **Защита от главной ошибки** — пропустить валидацию и 7 дней строить продукт, который не нужен рынку

**Принцип работы:**
- Вы — архитектор: принимаете ключевые решения (идти дальше или пивотить)
- Claude Code — исполнитель: строит MVP, лендинг, оплаты, деплоит, анализирует отклик
- Этот документ — общий язык между вами

**Как применять:**
```
Сценарий 1: Claude ведёт запуск
  Вы → даёте Claude идею + этот файл → Claude идёт по фазам и останавливает вас на критериях

Сценарий 2: Вы ведёте сами
  Вы → открываете чек-лист → отмечаете фазы по мере прохождения

Сценарий 3: Go/No-Go решение
  Вы/Claude → сверяете критерии «сделано» в конце фазы → решаете двигаться дальше или пивотить
```

---

## Зачем нужен этот документ

90% продуктов проваливаются не потому, что плохо сделаны, а потому, что решают несуществующую проблему. MVP (Minimum Viable Product) — это способ проверить идею за минимальное время и деньги.

Формула:
```
Валидация (2 дня) → Сборка MVP (7 дней) → Лендинг (1 день) → 
Оплаты (0.5 дня) → Первые 10 пользователей (7-14 дней) → Итерация
```

**Общий срок: 2-4 недели от идеи до первых платящих клиентов.**

**Правило:** Если ты тратишь на MVP больше 2 недель разработки — ты строишь не MVP, а полный продукт. Вернись к списку функций и выкини половину.

## Этап 1: Валидация идеи (2 дня)

### Цель: убедиться, что проблема реальна и за решение готовы платить

### 5 вопросов для валидации

Ответь на каждый вопрос. Если на 3+ из 5 ответ «нет» — идея требует доработки.

| # | Вопрос | Как проверить | Критерий «да» |
|---|--------|--------------|--------------|
| 1 | Существует ли проблема? | Поговори с 5 представителями ЦА | 4 из 5 подтвердили проблему |
| 2 | Как решают сейчас? | Спроси «что используете сегодня?» | Текущее решение имеет конкретные минусы |
| 3 | Готовы платить? | Спроси «сколько стоит эта проблема в месяц?» | Назвали конкретную сумму > 0 |
| 4 | Есть ли конкуренты? | Поиск в Google, Product Hunt, App Store | Конкуренты есть, но с явными слабостями |
| 5 | Я могу это построить? | Оценка стека, времени, бюджета | Реалистично за 7 дней с Claude Code |

### Инструменты для валидации

| Задача | Инструмент | Время |
|--------|-----------|-------|
| Поиск ЦА | Telegram-чаты, LinkedIn, тематические форумы | 2-3 часа |
| Опрос ЦА | Telegram DM, Google Forms | 3-4 часа |
| Анализ конкурентов | Claude AI + ручной поиск | 2-3 часа |
| Описание идеи | PROJECT_IDEA.md (шаблон 2-10) | 2-3 часа |

### Критерий «сделано»:
- [ ] Поговорил с 5+ людьми из целевой аудитории
- [ ] 3+ подтвердили проблему
- [ ] Определена цена проблемы (в деньгах или часах)
- [ ] Заполнен PROJECT_IDEA.md
- [ ] Список функций MVP: 3-5 штук (не больше 7)

## Этап 2: Сборка MVP (7 дней)

### Цель: рабочий продукт с 3-5 ключевыми функциями

### Дневной план

**День 1: Спецификация**

| Задача | Инструмент | Время |
|--------|-----------|-------|
| Написать SPEC.md на основе PROJECT_IDEA.md | Claude AI (web) | 3-4 часа |
| Проверить Data Model (таблицы, связи) | Claude AI | 1 час |
| Финализировать User Stories | Claude AI | 1 час |

Критерий «сделано»:
- [ ] SPEC.md содержит все 6 блоков (User Stories, Data Model, API, UI/UX, Business Logic, Edge Cases)
- [ ] SQL для создания таблиц готов
- [ ] Нет TODO и placeholder'ов в спецификации

**День 2: Настройка Claude Code**

| Задача | Инструмент | Время |
|--------|-----------|-------|
| Загрузить SPEC.md в Setup Generator | Claude AI (web) | 1-2 часа |
| Создать структуру проекта | Claude Code | 30 мин |
| Подключить MCP-серверы | CLI | 30 мин |
| Настроить Supabase (проект, таблицы, RLS) | Supabase Dashboard + MCP | 1-2 часа |
| Подключить GitHub репозиторий | CLI | 15 мин |

Критерий «сделано»:
- [ ] CLAUDE.md, субагенты, правила созданы
- [ ] MCP-серверы подключены (Supabase, Context7, GitHub)
- [ ] База данных создана и заполнена тестовыми данными
- [ ] Первый git commit сделан

**День 3-4: Бэкенд + API**

| Задача | Инструмент | Время |
|--------|-----------|-------|
| API routes по спецификации | Claude Code | 4-6 часов |
| Авторизация (Supabase Auth) | Claude Code | 2-3 часа |
| Бизнес-логика | Claude Code | 3-4 часа |
| RLS-политики | Claude Code | 1-2 часа |

Критерий «сделано»:
- [ ] Все API endpoints из спецификации работают
- [ ] Авторизация: регистрация, вход, выход
- [ ] RLS-политики настроены (пользователь видит только свои данные)
- [ ] Тестовые запросы через curl/Postman проходят

**День 5-6: Фронтенд**

| Задача | Инструмент | Время |
|--------|-----------|-------|
| Страницы по спецификации | Claude Code (Next.js + shadcn/ui) | 6-8 часов |
| Мобильная адаптация | Claude Code | 2-3 часа |
| Состояния: loading, error, empty | Claude Code | 1-2 часа |
| Подключение к API | Claude Code | 2-3 часа |

Критерий «сделано»:
- [ ] Все экраны из спецификации реализованы
- [ ] Мобильная версия работает
- [ ] Состояния loading/error/empty отображаются корректно
- [ ] Данные из API отображаются

**День 7: Интеграции + тестирование**

| Задача | Инструмент | Время |
|--------|-----------|-------|
| Telegram-бот (если нужен) | Claude Code + Node.js | 2-3 часа |
| Email-уведомления (если нужны) | Claude Code | 1-2 часа |
| Тестирование всех сценариев | Ручное | 2-3 часа |
| Исправление багов | Claude Code | 2-3 часа |

Критерий «сделано»:
- [ ] Все пользовательские сценарии проходят от начала до конца
- [ ] Интеграции работают (Telegram, email)
- [ ] Критичных багов нет
- [ ] Продукт можно показывать пользователям

## Этап 5: Первые 10 пользователей (7-14 дней)

### Цель: получить 10 реальных пользователей, собрать обратную связь

### Каналы привлечения

| Канал | Действие | Цель | Время |
|-------|----------|------|-------|
| Личные контакты | Написать 20-30 знакомым из ЦА | 3-5 пользователей | 1 день |
| Telegram-чаты | Публикация в 5-10 тематических чатах | 3-5 пользователей | 2-3 дня |
| Холодные сообщения | 50-100 сообщений по шаблону 9-52 | 3-5 пользователей | 5-7 дней |
| Контент (Reels/ТГ) | 3-5 постов о процессе создания | 2-3 пользователя | 7-14 дней |

### Скрипт для личных контактов

```
Привет! Я запустил [название продукта] — 
это [что делает] для [кого].

Ты как раз из тех, кому это может быть полезно. 
Сейчас у нас бесплатный ранний доступ — 
хочу собрать честный фидбек.

Попробуешь? Займёт 5 минут на регистрацию. 
Ссылка: [URL]

Буду благодарен за любой отзыв — 
что понравилось и что бесит.
```

### Сбор обратной связи

После каждого пользователя спроси:
1. Что было непонятно при первом использовании?
2. Какая функция самая полезная?
3. Чего не хватает? (записывай, но не делай сразу)
4. За какую цену готов платить ежемесячно?
5. Порекомендуешь коллеге? (0-10)

### Критерий «сделано»:
- [ ] 10+ зарегистрированных пользователей
- [ ] 5+ активно использовали продукт
- [ ] Собрана обратная связь от 5+ пользователей
- [ ] 1-3 платящих пользователя (или подтвердили готовность платить)
- [ ] Определены топ-3 проблемы для следующей итерации

## Этап 6: Итерация (непрерывно)

### Цель: улучшить продукт на основе реальных данных

### Приоритизация задач

```
1. Баги, которые блокируют использование → фиксить немедленно
2. Функции, которые просят 3+ пользователей → следующий спринт
3. Функции, которые просит 1 пользователь → записать, не делать
4. Твои «гениальные идеи» → проверить спросом, не кодить сразу
```

### Цикл итерации (каждые 1-2 недели)

```
Собрать фидбек → Определить топ-3 проблемы → 
Обновить SPEC.md → Реализовать через Claude Code → 
Задеплоить → Уведомить пользователей → Повторить
```

### Критерий «сделано» для каждой итерации:
- [ ] Топ-3 проблемы определены и приоритизированы
- [ ] Изменения реализованы и задеплоены
- [ ] Пользователи уведомлены о обновлениях
- [ ] Метрики (retention, churn) отслеживаются

## Антипаттерны (что НЕ делать)

1. **Не строить «идеальный» продукт.** MVP — это минимум. Если не стыдно показывать, значит выпустил слишком поздно.

2. **Не добавлять функции без запроса.** Каждая новая функция = время на разработку, тестирование и поддержку. Добавляй только то, что просят 3+ пользователей.

3. **Не пропускать валидацию.** «Мне кажется, это нужно людям» — не валидация. 5 разговоров с ЦА — валидация.

4. **Не откладывать подключение оплат.** Бесплатные пользователи не доказывают жизнеспособность. Платящий пользователь — единственное доказательство.

5. **Не тратить больше 7 дней на сборку.** Если продукт не готов за 7 дней — урежь функции, а не увеличивай срок.

---

*MVP — это не продукт. Это тест гипотезы. Цель не «сделать красиво», а «проверить, будут ли платить». Красиво сделаешь после того, как подтвердишь спрос.*
