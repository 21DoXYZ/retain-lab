> **Генератор:** промпт в конце этого документа

---

## Философия этого документа

**Вы не пишете кейс вручную.** Claude AI собирает его из данных по завершённому проекту (название, клиент, задача, решение, метрики, стек) через промпт, который лежит в конце этого документа.

Зачем тогда этот справочник?

1. **Валидация** — проверить, что Claude включил все 7 обязательных блоков (Задача → Решение → Процесс → Результаты → Скриншоты → Отзыв → Цифры)
2. **Корректировка** — если метрики абстрактные или отзыв звучит искусственно, знать что попросить переделать
3. **NDA-контроль** — убедиться, что нет реальных данных клиента
4. **Контроль языка** — проверить, что Claude не писал «комплексное решение» и прочий канцелярит

**Правильный workflow:**
```
Вы → собираете факты по проекту (название, стек, сроки, стоимость, метрики)
Claude → генерирует кейс через промпт внизу документа
Вы → используете этот справочник чтобы валидировать 7 блоков
Claude → вносит правки по вашим замечаниям
```

---

## Зачем нужны кейсы

- Клиент видит, что ты уже делал похожее
- Показывает процесс и результат, не только скриншоты
- Даёт конкретные метрики (сроки, цена, результаты)
- Снижает тревогу: «А вдруг не справится?»

**Правило:** 1 сильный кейс > 10 строчек в резюме.

## Что Claude вернёт для TaskFlow

Ниже — пример того, что Claude сгенерирует, если скормить промпт из конца документа с данными проекта TaskFlow. Используйте как образец для сравнения со своим результатом.

```markdown
# TaskFlow

> Трекер задач для фрилансеров с учётом времени
> и аналитикой рентабельности проектов

---

## Задача

### Клиент
ООО «Продуктив» — компания, разрабатывающая инструменты
продуктивности для самозанятых и фрилансеров. Аудитория:
5 000+ фрилансеров на платформе.

### Проблема
Фрилансеры из базы клиента использовали 3-4 разных инструмента
для организации работы: Trello для задач, Excel для учёта
времени, блокнот для заметок по проектам. Результат:
- 2-3 часа в день уходило на «организацию организации»
- 60% фрилансеров не знали рентабельность своих проектов
- 35% срывали дедлайны из-за отсутствия системы

### Цель проекта
Создать единый трекер задач, который объединяет управление
проектами, учёт времени и аналитику рентабельности в одном
веб-приложении с интеграцией в Telegram.

---

## Решение

### Что построили
TaskFlow — веб-приложение, где фрилансер ведёт все проекты,
задачи и учёт времени в одном месте. Канбан-доска для задач,
встроенный таймер, автоматический расчёт рентабельности по
каждому проекту и клиенту. Telegram-бот напоминает о задачах
и позволяет быстро фиксировать время без открытия браузера.

### Ключевые модули

| Модуль | Что делает |
|--------|------------|
| Дашборд | Сводка: часы за неделю, доход за месяц, активные проекты |
| Канбан-доска | Задачи с приоритетами, drag-n-drop между колонками |
| Таймер | Старт/стоп по задаче, автоматический подсчёт часов |
| Проекты | Бюджет, затраченное время, процент выполнения |
| Аналитика | Рентабельность по клиентам, экспорт отчётов в CSV |
| Telegram-бот | Уведомления о дедлайнах, создание задач командой /task |

### Технический стек

| Компонент | Технология |
|-----------|-----------|
| Frontend | Next.js 16 + TypeScript + Tailwind CSS v4 + shadcn/ui |
| Backend | Supabase (PostgreSQL, Auth, RLS, Realtime) |
| Бот | Node.js + grammy (Telegram Bot API) |
| Деплой | Vercel (фронт) + Beget VPS (бот) |
| CI/CD | GitHub Actions |

---

## Процесс

### Этапы работы

| Этап | Что делали | Срок |
|------|-----------|------|
| Спецификация | SPEC.md: user stories, data model, API, UI/UX | 2 дня |
| Setup | Claude Code Setup Generator → субагенты, rules, CLAUDE.md | 0.5 дня |
| Разработка | Автономная сборка через Claude Code: БД → API → UI | 2 недели |
| Telegram-бот | Node.js бот с командами и уведомлениями | 3 дня |
| Тестирование | Функциональное тестирование, правки, полировка UI | 3 дня |
| Деплой | Vercel + VPS + домен + SSL | 1 день |
| **Итого** | | **3.5 недели** |

### Подход
Проект разработан по методологии Spec-First: полная
спецификация перед началом кода. Claude Code с 4 субагентами
(database-architect, backend-engineer, frontend-developer,
qa-reviewer) реализовывал задачи автономно по спецификации.
Итерации через естественный язык, каждое изменение —
git commit.

## Чек-лист валидации (после генерации)

Когда Claude вернул кейс — пройдитесь по этому чек-листу. Если что-то не так, попросите Claude исправить конкретный блок.

- [ ] Все 7 блоков присутствуют: Задача / Решение / Процесс / Результаты / Скриншоты / Отзыв / Цифры
- [ ] Метрики — конкретные числа, а не «улучшили», «повысили»
- [ ] Таблица «До / После / Изменение» заполнена (минимум 3 метрики)
- [ ] Отзыв клиента — не шаблонный «спасибо большое», а с конкретикой
- [ ] Стек указан полностью (Frontend / Backend / Database / Деплой)
- [ ] Нет реальных данных клиента (NDA-чек: название компании, имена, URL)
- [ ] Длина — 200-300 строк для полного кейса
- [ ] Нет «ИИ-канцелярита» («комплексное решение», «ключевые особенности»)
- [ ] Указан срок, стоимость, экономия клиента
- [ ] Плейсхолдеры для скриншотов отмечены (их нужно добавить руками)

**Если найдена проблема — промпт для исправления:**
```
В кейсе проблема: [что не так, например: "метрики абстрактные"].
Перепиши только блок [X]. Добавь конкретные цифры и формат «До / После / %».
```

## Советы по оформлению кейсов

### Где публиковать

| Площадка | Формат | Аудитория |
|----------|--------|-----------|
| Личный сайт | Полный кейс (эта структура) | Клиенты, приходящие по рекомендации |
| Telegram-канал | Краткий пост (3-5 абзацев) + 2-3 скриншота | Подписчики |
| Behance / Dribbble | Визуальный кейс (скриншоты + описание) | Дизайн-сообщество |
| GitHub | README.md + live demo | Техническая аудитория |
| LinkedIn | Пост с метриками + ссылка | B2B-клиенты |

### Что НЕ включать в кейс

- Реальные данные клиента (NDA)
- Исходный код (ссылка на приватный репозиторий)
- Финансовые детали клиента (выручка, контракты)
- Скриншоты с реальными пользовательскими данными

### Сколько кейсов нужно

| Кол-во | Эффект |
|:------:|--------|
| 0 | Клиенты не доверяют — «нет опыта» |
| 1-2 | Минимум для доверия |
| 3-5 | Оптимально — закрывает разные типы проектов |
| 10+ | Избыточно — клиент не будет читать все |

**Рекомендация:** 3-5 кейсов, покрывающих разные типы проектов:
1. SaaS / веб-приложение
2. Telegram-бот / MiniApp
3. AI-автоматизация / агент
4. Лендинг / интернет-магазин
5. Интеграция / API-проект

```

  ↓ Загрузите:
  • Этот справочник (8-49) — как reference структуры
  • Промпт ниже
  
ШАГ 3: Вставьте промпт с подставленными данными
  
ШАГ 4: Получите результат
  ↓ Claude вернёт полный кейс + короткую версию для Telegram

ШАГ 7: Публикация: сайт / Telegram / LinkedIn / GitHub
