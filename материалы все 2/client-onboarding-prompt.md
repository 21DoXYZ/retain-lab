# 1-09: Промпт для онбординга клиента

> **Тип:** Инструкция (промпт для Claude AI)
> **Фаза:** Первый контакт / Обработка входящего запроса
> **Время применения:** Клиент прислал бриф, запрос или описание проекта
> **Результат:** Структурированный разбор запроса, выявленные пробелы, уточняющие вопросы, предварительный скоуп

---

## Философия этого документа

Этот файл — **готовый промпт для Claude AI**. Вы не пишете его сами — копируете и используете.

**Принцип работы:**
- Вы — архитектор и коммуникатор
- Claude — исполнитель: читает промпт, делает работу
- Ваша задача — описать контекст и скопировать правильный промпт

**Workflow:**
```
Вы → копируете промпт → загружаете в Claude AI (web)
       ↓
       прикрепляете свой контекст (бриф клиента / переписка / голосовое)
       ↓
Claude → выполняет задачу по промпту
       ↓
Вы → получаете результат → используете в проекте
```

Промпт уже отлажен. Не нужно его улучшать с первого раза — просто используйте.

---

## Зачем нужен этот промпт

Когда потенциальный клиент присылает запрос на разработку (в Telegram, по почте, через форму на сайте), нужно быстро:

1. **Понять масштаб проекта** — это лендинг или enterprise-платформа?
2. **Выявить пробелы** — что клиент не описал, но это критично для оценки
3. **Сформировать уточняющие вопросы** — конкретные, по делу, не абстрактные
4. **Предложить структуру работы** — Discovery Sprint, этапы, ориентир по срокам
5. **Написать профессиональный ответ** — который продаёт экспертизу, а не «перезвоните»

**Проблема:** На всё это уходит 1-2 часа ручной работы. С этим промптом — 5 минут.

**Когда использовать:**
- Клиент прислал бриф любого формата (от одного абзаца до 10-страничного ТЗ)
- Клиент задаёт вопросы о стоимости, подходе, сроках
- Нужно быстро оценить, стоит ли браться за проект
- Нужно сформировать ответ, который покажет экспертизу

**Когда НЕ использовать:**
- Клиент уже в работе и присылает правки по текущему проекту
- Запрос явно не по профилю (например, разработка мобильной игры)

## Промпт для Claude AI

Скопируй промпт ниже в Claude AI (веб-версия). Вставь бриф клиента в указанное место.

---

```
Ты — бизнес-аналитик в AI-агентстве, которое специализируется на разработке
сложных цифровых продуктов: SaaS-платформы, B2B-маркетплейсы, AI-системы
автоматизации, внутренние бизнес-инструменты.

Методология агентства — Spec-Driven Development:
1. Discovery Sprint (Этап 0) — платное исследование, прототип на данных клиента
2. MVP (Этап 1) — рабочий продукт с ключевой функциональностью
3. Итерации (Этапы 2+) — расширение на основе обратной связи пользователей

Стек: Next.js + TypeScript, Supabase (PostgreSQL), Tailwind CSS, Node.js на VPS,
AI-агенты через Claude API.

Подход к разработке: инженеры пишут детальные спецификации, затем команда
специализированных AI-субагентов (database-architect, backend-engineer,
frontend-developer, qa-reviewer) работает под управлением архитекторов.
Это сокращает сроки в 2-3 раза по сравнению с классическими студиями.

Клиент прислал запрос на разработку. Проанализируй его и выдай
структурированный ответ по следующему плану:

## 1. РАЗБОР ЗАПРОСА

### 1.1 Тип проекта
Определи категорию: SaaS / Маркетплейс / Внутренний инструмент / Бот /
Автоматизация / Лендинг+CRM / Другое

### 1.2 Масштаб
Оцени сложность: Простой (1-2 мес) / Средний (2-4 мес) / Сложный (4-8 мес) /
Enterprise (8+ мес)

### 1.3 Ключевые компоненты
Перечисли основные модули/фичи, которые клиент описал. Для каждого укажи:

- Что делает (в одном предложении)
- Техническая сложность: Низкая / Средняя / Высокая

### 1.4 Неявные требования
Что клиент НЕ упомянул, но это точно понадобится:
- Авторизация и роли

- Уведомления (email, push, Telegram)
- Админ-панель

- Интеграции с внешними сервисами
- Compliance (152-ФЗ, NDA, и т.д.)

## 2. ВЫЯВЛЕННЫЕ ПРОБЕЛЫ

Для каждого пробела:
- Что неясно
- Почему это критично для оценки
- Как это влияет на стоимость и сроки

Минимум 5 пробелов, максимум 10.

## 3. УТОЧНЯЮЩИЕ ВОПРОСЫ

Сформируй список из 7-12 конкретных вопросов клиенту.

Правила:
- Каждый вопрос должен влиять на стоимость или архитектуру
- Никаких абстрактных «расскажите подробнее» — только конкретика
- Группируй по темам: Бизнес-логика / Пользователи / Данные /
  Интеграции / Монетизация
- Формат: вопрос + почему спрашиваем (в скобках)

## 4. ПРЕДВАРИТЕЛЬНЫЙ СКОУП

### 4.1 Рекомендация по этапности

Раздели проект на этапы:
- Discovery Sprint: что проверяем, какие гипотезы, какие данные нужны
- MVP: минимальный набор модулей для запуска (НЕ всё, что клиент хочет)
- Этап 2: что добавляем после получения обратной связи от пользователей
- Этап 3+ (если применимо): масштабирование

### 4.2 Ориентир по срокам
Для каждого этапа — предварительная оценка в неделях.
Подчеркни, что точные сроки — после Discovery.

### 4.3 Риски
Перечисли 3-5 основных рисков проекта и как Discovery Sprint их снижает.

## 5. ЧЕРНОВИК ОТВЕТА КЛИЕНТУ

Напиши готовое сообщение клиенту в Telegram (3-5 абзацев).

Тон: профессиональный, но не формальный. Без канцелярита.
Обращение: на «вы».

Структура ответа:
1. Подтверждение, что бриф изучен, показать понимание масштаба
2. 3-5 ключевых уточняющих вопросов (самых важных из списка выше)
3. Предложение формата работы: Discovery Sprint → MVP → итерации
4. Объяснение подхода к ценообразованию: «стоимость формируется после
   анализа, не "на глаз"»
5. Конкретный следующий шаг: «предлагаю созвон на 30 мин»

Важно включить в ответ:
- Мы подписываем NDA на работу, доступы и данные клиента
- Все аккаунты и инфраструктура могут оформляться на стороне клиента
  (при условии предоплаты по этапам)
- Стоимость инструментов разработки в смету не входит — это наши расходы
- Работаем по этапам с фиксированной стоимостью каждого этапа
```

Секции 1-4 — готовая основа для документа Talking Points (1-08) перед звонком.

## Пример: Онбординг Ивана Петрова (TaskFlow)

### Входящее сообщение клиента

> Здравствуйте! Меня зовут Иван, компания ООО "Продуктив".
>
> Мы работаем с фрилансерами (дизайнеры, копирайтеры, разработчики) и видим
> проблему: у людей нет нормального инструмента для планирования рабочего дня.
> Существующие трекеры (Trello, Notion, Todoist) — это просто списки задач. Они не
> учитывают дедлайны, загрузку, приоритеты, энергию человека.
>
> Хотим сделать TaskFlow — AI-трекер, который:
> - Импортирует задачи из разных источников (Trello, Notion, Google Calendar)
> - AI анализирует задачи: сложность, время, зависимости
> - Строит оптимальный план дня с учётом дедлайнов и энергии
> - Учится на поведении пользователя (что откладывает, что делает быстро)
> - Показывает аналитику продуктивности
>
> Модель монетизации — подписка. Бесплатный тариф с ограничениями, платный ~500 руб/мес.
>
> Сколько это может стоить и за какие сроки реально сделать?
> Бюджет ограничен, но готовы инвестировать в качественный продукт.

---

### Результат работы промпта

#### 1. РАЗБОР ЗАПРОСА

**Тип проекта:** SaaS-платформа с AI-компонентом

**Масштаб:** Средний (3-4 месяца до MVP)

**Ключевые компоненты:**

| Модуль | Описание | Сложность |
|--------|----------|-----------|
| Импорт задач | Интеграция с Trello API, Notion API, Google Calendar API | Средняя |
| AI-классификатор | Анализ задач: определение сложности, времени, зависимостей | Высокая |
| Планировщик дня | Алгоритм оптимального расписания с учётом ограничений | Высокая |
| Система обучения | Модель, которая учится на поведении пользователя | Высокая |
| Аналитика | Дашборды продуктивности, статистика выполнения | Средняя |
| Биллинг | Подписки, бесплатный/платный тариф, оплата | Средняя |

**Неявные требования (клиент не упомянул):**
- Авторизация (email, Google OAuth)
- Лендинг / маркетинговый сайт
- Онбординг нового пользователя
- Email-уведомления и push-нотификации
- Мобильная адаптация (PWA)
- Админ-панель для управления подписками
- Политика конфиденциальности (152-ФЗ)
- Интеграция с ЮKassa для платежей в России

#### 2. ВЫЯВЛЕННЫЕ ПРОБЕЛЫ

| # | Пробел | Почему критично | Влияние |
|:-:|--------|----------------|---------|
| 1 | Не описано, как именно AI определяет «энергию» пользователя | Это ключевая фича — нужно понять, какие данные собираем | Может удвоить сроки AI-модуля |
| 2 | Нет информации о целевом количестве пользователей на старте | Влияет на архитектуру: 100 или 10,000 пользователей — разные решения | Влияет на стоимость инфраструктуры |
| 3 | Не указано, какие интеграции критичны для MVP | Trello + Notion + Google Calendar = три API, на MVP может хватить одного | Каждая интеграция = +1-2 недели |
| 4 | Модель «учится на поведении» — нужна конкретика | Это ML-модель или эвристики? Offline или online learning? | Может быть от 1 до 8 недель работы |
| 5 | «Бюджет ограничен» — нет конкретной цифры | Невозможно предложить адекватный скоуп без понимания рамок | Может означать 100K или 1M рублей |
| 6 | Не описана командная работа | TaskFlow только для индивидуалов или есть командный режим? | Командный режим = отдельный модуль |
| 7 | Нет информации о конкурентном анализе | Может быть, уже есть аналоги с AI — нужно отстроиться | Влияет на позиционирование |

#### 3. УТОЧНЯЮЩИЕ ВОПРОСЫ

**Бизнес-логика:**
1. Что именно вы имеете в виду под «энергией человека»? Пользователь сам отмечает своё состояние, или система определяет по паттернам поведения? (определяет сложность AI-модуля)
2. TaskFlow — только для индивидуальных фрилансеров или планируете командный режим? (влияет на архитектуру и стоимость)
3. Какие из интеграций критичны на первом этапе? Можем ли начать с одной (например, Trello) и добавлять остальные после запуска? (сокращает MVP в 2 раза)

**Пользователи:**
4. Сколько пользователей ожидаете в первые 3 месяца после запуска? (определяет архитектуру)
5. Есть ли уже база потенциальных пользователей или аудитория для тестирования? (влияет на стратегию запуска)

**Данные:**
6. Есть ли у вас реальные данные задач фрилансеров, на которых можно протестировать AI? Нам нужно 50-100 реальных задач для Discovery Sprint. (критично для проверки гипотезы)

**Монетизация:**
7. Какие ограничения у бесплатного тарифа: количество задач, количество проектов, отсутствие AI-планировщика? (влияет на конверсию и архитектуру)

**Бюджет:**
8. Какой бюджетный диапазон вы рассматриваете для первого этапа (MVP)? Это поможет определить, какой набор функций реально реализовать. (определяет скоуп)

#### 4. ПРЕДВАРИТЕЛЬНЫЙ СКОУП

**Discovery Sprint (Этап 0) — 2 недели, 80,000 ₽:**
- Проверяем: может ли AI корректно классифицировать задачи и строить план дня
- Тестируем на 50 реальных задачах клиента
- Результат: работающий прототип AI-планировщика + точная смета MVP

**MVP (Этап 1) — 6-8 недель:**
- Auth (email + Google)
- Импорт задач из одного источника (Trello)
- AI-классификатор задач
- Планировщик дня (базовый)
- Базовая аналитика
- Подписка (бесплатный + платный тариф)
- Лендинг

**Этап 2 — 4-6 недель (после получения обратной связи от пользователей):**
- Notion и Google Calendar интеграции
- Система обучения на поведении
- Расширенная аналитика
- Push-уведомления
- Мобильная PWA-версия

**Риски:**
1. AI-классификатор может быть неточным на специфических задачах — Discovery Sprint это проверяет
2. «Учёт энергии» может оказаться слишком субъективным — нужны данные для валидации
3. Три API-интеграции одновременно замедлят MVP — рекомендуем начать с одной

#### 5. ЧЕРНОВИК ОТВЕТА КЛИЕНТУ

> Иван, добрый день! Спасибо за подробное описание проекта.
>
> Изучил ваш бриф — проект понятный и перспективный. Фактически речь идёт о SaaS-платформе с AI-ядром: классификация задач, построение оптимального плана, обучение на поведении пользователя. Это не тривиальный трекер, а полноценный AI-продукт.
>
> Несколько вопросов, которые повлияют на стоимость и сроки:
> 1. Какие интеграции критичны на старте? Если начать с одного источника (Trello), MVP будет быстрее и дешевле. Остальные добавим на следующем этапе.
> 2. «Учёт энергии» — как вы это видите? Пользователь сам отмечает или система определяет по паттернам? Это влияет на сложность AI-модуля.
> 3. Какой бюджетный ориентир на первый этап? Поможет предложить адекватный скоуп.
>
> По формату работы: мы работаем по этапам. Первый шаг — Discovery Sprint (2 недели): мы берём 50 ваших реальных задач, собираем прототип AI-планировщика и проверяем, насколько точно он работает на ваших данных. По итогам — фиксированная смета на MVP без вилок. Стоимость Discovery — 80 000 рублей, 100% предоплата.
>
> Важные моменты: мы подписываем NDA на все данные и доступы. Все аккаунты и инфраструктура могут быть оформлены на вашей стороне. Стоимость инструментов разработки в смету не входит — это наши расходы.
>
> Предлагаю созвон на 30 минут — обсудим детали и отвечу на все вопросы. Когда удобно на этой неделе?

## Адаптация промпта под разные типы проектов

### Если клиент прислал очень короткий запрос (1-2 предложения)

Добавь в конец промпта:

```
ДОПОЛНИТЕЛЬНО: Запрос клиента очень краткий. В секции «Уточняющие вопросы»
увеличь количество до 12-15 вопросов. В черновике ответа сделай акцент
на необходимости более детального брифа перед оценкой.
```

### Если клиент прислал развёрнутое ТЗ (10+ страниц)

Добавь в конец промпта:

```
ДОПОЛНИТЕЛЬНО: Клиент прислал детальное ТЗ. В секции «Разбор запроса»
выдели bounded contexts и предложи декомпозицию на микросервисы (если
применимо). В секции «Предварительный скоуп» предложи 4-5 этапов
вместо стандартных 3.
```

### Если клиент спрашивает только о стоимости

Добавь в конец промпта:

```
ДОПОЛНИТЕЛЬНО: Клиент фокусируется на стоимости. В черновике ответа
объясни, почему мы не называем цену без анализа (аналогия: «врач не
ставит диагноз по телефону»). Предложи Discovery Sprint как способ
получить точную цифру. Дай ориентировочные диапазоны по типам проектов:
- Бот / автоматизация: 50-200K ₽
- SaaS MVP: 300-800K ₽
- Платформа / маркетплейс: 800K-3M ₽
- Enterprise-система: от 3M ₽
```

### Если клиент из конкретной отрасли

Добавь в конец промпта:

```
ДОПОЛНИТЕЛЬНО: Клиент из отрасли [НАЗВАНИЕ]. Учти отраслевую специфику
в анализе:
- Регуляторные требования (если есть)
- Типичные интеграции для этой отрасли
- Примеры аналогичных продуктов на рынке
- Специфические риски отрасли
```
