## Философия этого документа

**Вы не пишете КП вручную.** Claude AI генерирует его из вашего описания проекта и данных по клиенту через `8-44-KP_GENERATOR_PROMPT.md`.

Зачем тогда этот справочник?

1. **Валидация** — понять, правильно ли Claude построил структуру КП
2. **Корректировка** — если что-то не так, знать как попросить переделать конкретный раздел
3. **Коммуникация** — говорить с Claude на языке "усиль ценовой якорь" вместо "это не то"
4. **Контроль качества** — проверить, что КП не содержит ИИ-канцелярита и укладывается в 3-6 страниц

**Правильный workflow:**
```
Вы → описываете проект и клиента (бриф)
Claude → генерирует КП через KP_GENERATOR_PROMPT
Вы → используете этот справочник чтобы валидировать результат
Claude → вносит правки по вашим замечаниям
```

## Чек-лист валидации (после генерации)

Когда Claude вернул КП — пройдитесь по этому чек-листу. Если что-то не так, попросите Claude исправить.

- [ ] Убраны все технические термины, непонятные клиенту
- [ ] Есть ценовой якорь (рыночная цена vs наша цена)
- [ ] Стоимость фиксированная, не вилка (вилки выглядят неуверенно)
- [ ] Сроки конкретные, не «от X до Y месяцев»
- [ ] Указано, что входит и что НЕ входит (защита от scope creep)
- [ ] Условия оплаты прописаны чётко (суммы, а не только проценты)
- [ ] Есть раздел «Следующие шаги» с конкретным действием
- [ ] Документ проверен на «ИИ-канцелярит» (убраны: «комплексный», «всесторонний», «ключевые особенности», «инновационный»)
- [ ] Длина КП — 3-6 страниц (не 10+)
- [ ] Контактные данные в конце

**Если найдена проблема — промпт для исправления:**

## Принципы эффективного КП

### Ценовой якорь

Всегда показывай сравнение рыночной цены и своей. Это не «демпинг» — это демонстрация эффективности AI-стека. Клиент должен видеть, сколько он экономит.

### Value-first, не feature-first

Не пиши «Модуль авторизации с JWT и RLS-политиками». Пиши «Безопасный вход с разделением прав доступа». Клиенту важен результат, не реализация.

### Фиксированные цены

Вилки цен (500-700K) создают впечатление, что ты сам не знаешь сколько это стоит. Ставь одну цифру. Если не уверен — бери верхнюю границу вилки.

### Язык документа

Избегай канцелярита и типичных ИИ-оборотов:
- ~~«Комплексное решение»~~ → «Готовый продукт»
- ~~«Всесторонний анализ»~~ → «Анализ»
- ~~«Ключевые особенности»~~ → «Что входит»
- ~~«Инновационный подход»~~ → «Наш подход» (или просто убрать)

### Длина

3-6 страниц. Не больше. Если клиенту нужна детализация — дай отдельно смету (см. `8-45-COST_ESTIMATION_TEMPLATE.md`).

```

  ↓ Название, описание, модули, ориентир по стоимости, срокам, клиенту

  ↓ Загрузите 2 файла:

ШАГ 3: Промпт:
  "Сгенерируй КП для проекта [название]. Вот бриф: [...].
   Следуй структуре из 8-43 и правилам из генератора."
  
ШАГ 4: Получите результат
  ↓ Claude вернёт полный КП по 8 секциям
  
ШАГ 5: Валидация (чек-лист выше)
  ↓ Пройдитесь по 10 пунктам

  "В разделе [X] проблема [Y]. Перепиши только этот раздел."

```

**Итог:** вы не написали ни одной строки КП руками. Вы описали проект, валидировали результат, дали правки. Это работа архитектора, а не копирайтера.
