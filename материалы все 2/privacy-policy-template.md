> Тип: Reference

> Для кого: AI-Архитектор, валидирующий сгенерированную политику конфиденциальности

---

## Философия этого документа

**Вы не пишете политику конфиденциальности вручную.** Claude сам генерирует её из вашего описания проекта и реквизитов юрлица через `7-42-LEGAL_DOCS_GENERATOR_PROMPT.md`.

Зачем тогда этот справочник?

1. **Валидация** — понять, правильно ли Claude построил структуру по 152-ФЗ
2. **Корректировка** — если что-то не так, знать как попросить изменить
3. **Коммуникация** — говорить с Claude на языке "добавь раздел о трансграничной передаче" вместо "политика плохая"
4. **Контроль качества** — проверить, что все реквизиты подставлены, нет placeholder'ов, ссылки на законы актуальные

**Правильный workflow:**
```
Вы → собираете данные: реквизиты юрлица (ИНН, ОГРН, адрес), описание продукта,
      список обработчиков данных (платёжка, AI-провайдер, аналитика)
Claude → генерирует privacy policy через Legal Docs Generator Prompt
Вы → используете этот справочник чтобы валидировать результат
Claude → вносит правки по вашим замечаниям
Вы → публикуете на /privacy-policy
```

**КРИТИЧНО:** всегда показывайте итоговую политику юристу перед публикацией, если проект обрабатывает чувствительные данные (медицина, финансы, дети).

#### 2. Назначение Платформы

2.1. {{PLATFORM_NAME}} — это {{PLATFORM_DESCRIPTION}}.

#### 3. Перечень обрабатываемых персональных данных

3.1. **Данные аккаунта:**
- Адрес электронной почты
- Имя и фамилия (при указании в профиле)
- Пароль (в зашифрованном виде)

- Идентификатор платежа

Оплата обрабатывается платёжным сервисом {{PAYMENT_PROVIDER}}. Оператор не хранит данные банковских карт — они обрабатываются исключительно на стороне платёжного сервиса в соответствии со стандартом PCI DSS.

> **Примечание:** Добавьте сюда специфичные для вашего проекта данные. Например, если вы обрабатываете фотографии, аудиозаписи, геолокацию — опишите каждый тип отдельным пунктом.

#### 4. Цели обработки персональных данных

4.1. Персональные данные обрабатываются в следующих целях:
- Регистрация и идентификация пользователя на Платформе
- Предоставление доступа к функционалу Платформы
- Обработка платежей и управление подписками
- Техническая поддержка пользователей
- Улучшение качества работы Платформы
- Выполнение требований законодательства Российской Федерации

#### 5. Правовые основания обработки

5.1. Обработка персональных данных осуществляется на основании:
- Согласия субъекта персональных данных (п. 1 ч. 1 ст. 6 ФЗ-152)
- Исполнения договора, стороной которого является субъект персональных данных (п. 5 ч. 1 ст. 6 ФЗ-152)
- Законных интересов Оператора при условии, что они не нарушают права субъекта (п. 7 ч. 1 ст. 6 ФЗ-152)

#### 6. Хранение и защита данных

6.1. Персональные данные хранятся на серверах, расположенных на территории Российской Федерации, в соответствии с требованиями ч. 5 ст. 18 Федерального закона N 152-ФЗ.

6.2. Для защиты персональных данных применяются:
- Шифрование данных при передаче (SSL/TLS)
- Шифрование данных при хранении
- Разграничение доступа на уровне строк базы данных (Row Level Security)
- Регулярное резервное копирование
- Многофакторная аутентификация для административного доступа

6.3. Доступ к персональным данным имеют только уполномоченные лица Оператора и автоматизированные системы обработки.

#### 7. Передача данных третьим лицам

7.1. Для предоставления услуг Оператор использует следующих обработчиков данных:

| Обработчик | Назначение | Данные |
|-----------|-----------|--------|
| {{PAYMENT_PROVIDER}} | Обработка платежей | Платёжные данные |

> **Примечание:** Добавьте сюда всех третьих лиц, которым передаются данные (AI-провайдеры, аналитика, хостинг и т.д.)

7.2. Все перечисленные обработчики данных обязуются соблюдать конфиденциальность и используют данные исключительно для выполнения своих функций.

7.3. Трансграничная передача персональных данных (если применимо) осуществляется в соответствии с главой 12 ФЗ-152 "О персональных данных".

7.4. Оператор не продаёт, не сдаёт в аренду и не передаёт персональные данные третьим лицам в маркетинговых целях.

#### 8. Сроки хранения данных

8.1. Персональные данные хранятся в течение всего периода использования Платформы пользователем и в течение 30 дней после удаления аккаунта.

8.2. Данные о платежах хранятся в течение сроков, установленных законодательством РФ о бухгалтерском учёте (5 лет).

8.3. Логи доступа и согласия хранятся в течение 3 лет.

## Чек-лист валидации (после генерации)

Когда Claude сгенерировал политику — пройдитесь по этому чек-листу. Если что-то не так, попросите исправить.

```
[ ] 1. Все реквизиты юрлица подставлены (ИНН, ОГРН, адрес)
[ ] 2. Нет ни одного placeholder'а вида {{...}} или [Описание]
[ ] 3. Ссылка на 152-ФЗ корректная ("Федеральный закон от 27.07.2006 N 152-ФЗ")
[ ] 4. Указан реестр Роскомнадзора (если оператор зарегистрирован)
[ ] 5. Перечислены ВСЕ обработчики данных (платёжка, AI, аналитика, хостинг)
[ ] 6. Указаны специфичные для проекта персональные данные (не только email/имя)
[ ] 7. Есть раздел о хранении данных на территории РФ (ч. 5 ст. 18 152-ФЗ)
[ ] 8. Перечислены права субъекта ПД (ст. 14 152-ФЗ)
[ ] 9. Указан email для запросов по ПД
[ ] 10. Есть дата публикации и версия документа
```

**Если найдена проблема — промпт для исправления:**
```
В сгенерированной политике конфиденциальности проблема: [что не так].
Исправь и убедись, что все реквизиты подставлены и ссылки на 152-ФЗ актуальные.
```

## Workflow: как создать Privacy Policy за 10 минут

```
ШАГ 1: Соберите данные юрлица и проекта
  ↓ Реквизиты (ИНН, ОГРН, адрес, реестр РКН),
    описание продукта, список обработчиков данных
  
ШАГ 2: Откройте Claude AI (web)
  ↓ Загрузите 2 файла:
  • Ваши данные (можно просто списком в промпте)
  • 7-42-LEGAL_DOCS_GENERATOR_PROMPT.md (из toolkit)
  
ШАГ 3: Промпт:
  "Сгенерируй политику конфиденциальности для этого SaaS-проекта
   по инструкциям из Legal Docs Generator Prompt.
   Учти 152-ФЗ, 149-ФЗ и все обработчики данных из списка."
  
ШАГ 4: Получите результат
  ↓ Claude вернёт готовую политику в формате Markdown
  
ШАГ 5: Валидация (этот документ)
  ↓ Пройдитесь по чек-листу выше
  
ШАГ 6: Если нужны правки — попросите Claude
  "В политике нет раздела о [X]. Добавь его с учётом 152-ФЗ."
  
ШАГ 7: Отдайте юристу на проверку (если проект с чувствительными данными)
  
ШАГ 8: Опубликуйте на /privacy-policy
```

**Итог:** вы не написали ни одной строки политики вручную. Вы собрали данные, валидировали результат, дали правки. Это роль архитектора.
