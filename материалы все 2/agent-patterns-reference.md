# 7 переносимых паттернов AI-агента

> **Главный артефакт урока про AI-агента «Финансовый директор».** Финансы — лишь пример. Вот 7 кирпичиков, из которых собирается ЛЮБОЙ агент: для продаж, поддержки, операций, аналитики. Распечатай или держи открытым — это твой конструктор.

---

## Паттерн 1 — Три слоя

**Суть:** интерфейс / бизнес-логика / AI — раздельно.

```
Интерфейс (bot, web, api)  →  только ввод-вывод
Бизнес-логика (services)   →  чистые функции, без AI
AI-слой (ai)               →  Claude решает, что вызвать
```

**Почему работает:** меняешь интерфейс не трогая логику; тестируешь логику без AI; AI не лезет в БД напрямую.

**Где в коде:** папки `src/bot/`, `src/services/`, `src/ai/`.

**Перенос:** агент поддержки — `bot/` (виджет на сайте), `services/` (поиск по базе, создание тикета), `ai/` (Claude решает: ответить или эскалировать).

---

## Паттерн 2 — Единый формат + дедупликация

**Суть:** любой вход нормализуй в один формат, защищайся от дублей хешем.

```
4 разных банка → detectSource() → 1 формат ParsedTransaction
hash = SHA-256(date|amount|counterparty|description)
INSERT ... ON CONFLICT (hash) DO NOTHING
```

**Почему работает:** дальше весь код работает с одним форматом; повторный импорт не плодит дубли.

**Где в коде:** `src/parsers/index.ts` (`detectSource`), `src/utils/hash.ts`.

**Перенос:** импорт лидов из разных источников (формы, реклама, выгрузки) → единый формат Lead → дедуп по email/телефону.

---

## Паттерн 3 — Tool-Use Loop (ядро агента)

**Суть:** агент = цикл, где Claude просит вызвать функции, ты выполняешь, он думает дальше.

```
дать Claude: системный промпт + список tools + историю
while (Claude просит инструмент):
    выполнить функцию → вернуть результат Claude
вернуть финальный ответ
```

**Почему работает:** Claude сам разбивает задачу на шаги и выбирает инструменты. Ты пишешь функции, он — оркестрирует.

**Где в коде:** `src/ai/tools.ts` (описания), `src/ai/toolHandlers.ts` (реализация), `src/ai/smartAgent.ts` (цикл).

**Перенос:** ЭТО — основа любого агента. Опиши свои функции как tools (`search_crm`, `send_email`, `create_invoice`) — Claude сам сообразит, когда их звать.

> ⚠️ Главное запомнить: **агент — это не чат, а цикл вызова инструментов.** Терминология Anthropic — Tool Use (не «function calling», это OpenAI).

---

## Паттерн 4 — Правильная модель под задачу

**Суть:** не лей всё в самую мощную модель. Подбирай по задаче.

| Задача | Модель | Логика |
|---|---|---|
| Рассуждение, аналитика | Opus (дорогая) | нужен глубокий reasoning |
| Классификация, разметка | Haiku (дешёвая) | reasoning не нужен, экономия 15-20× |
| Зрение (скриншоты) | Sonnet | баланс цена/качество |
| Поиск по смыслу | embeddings (Voyage) | не Claude вообще |

**Где в коде:** `src/ai/config.ts` (константы моделей).

**Перенос:** в любом агенте раздели задачи. Сортировка тикетов по темам — Haiku. Написание сложного ответа клиенту — Opus. Это экономит бюджет в разы.

## Паттерн 5 — Трёхуровневая память

**Суть:** агент помнит на трёх горизонтах.

```
1. Короткая (диалог)      — последние N сообщений, обычная таблица
2. Долгая смысловая       — эмбеддинги + векторный поиск (pgvector)
3. Граф знаний            — entities + relations (связи сущностей)
```

**Почему работает:** «а в мае?» (уровень 1), «что было с этим клиентом 3 месяца назад?» (уровень 2), «кто с кем связан?» (уровень 3).

**Где в коде:** `conversations`, `memory_nodes`, `entities`/`relations` + `src/services/memoryService.ts`, `graphService.ts`.

**Перенос:** боту поддержки хватит уровня 1 + базы знаний на эмбеддингах (уровень 2). Бери что нужно под задачу — не всё сразу.

## Паттерн 6 — propose + confirm для изменений

**Суть:** агент читает молча, но меняет данные только с подтверждения.

```
ШАГ 1 propose:  «Готов сделать X (затронет N записей). Применить?» + [✅] [❌]
ШАГ 2 apply:    меняем данные только после подтверждения
```

**Почему работает:** AI ошибается. Право молча перезаписывать базу = катастрофа. Подтверждение = страховка + пользователь видит что будет.

**Где в коде:** таблица `proposals` + propose-tools в `src/ai/toolHandlers.ts`.

**Перенос:** любой агент, который пишет/отправляет/удаляет (рассылку, инвойс, изменение в CRM) — подтверждай. Чтение можно молча.

## Паттерн 7 — Логирование стоимости с первого дня

**Суть:** каждый AI-вызов пишется (модель, токены, latency, деньги). Регулярный отчёт.

```
каждый вызов Claude → agent_logs (input/output/cache tokens)
ежедневно → отчёт «потрачено $X»
+ prompt caching → экономия до 70%
```

**Почему работает:** AI стоит денег. Без учёта — сюрприз в конце месяца. С учётом — видишь что оптимизировать.

**Где в коде:** `src/utils/logger.ts` (`logAgentCall`), `src/services/costService.ts`, `agent_logs`.

**Перенос:** встрой учёт стоимости в КАЖДЫЙ агент сразу, а не «потом». Это часть архитектуры, не опция.

## Чек-лист «мой агент готов архитектурно»

```
[ ] Разделил на 3 слоя (интерфейс / логика / AI)
[ ] Любой вход нормализуется в единый формат + есть дедуп
[ ] Есть tool-use loop: функции описаны как tools
[ ] Задачи разведены по моделям (дорогая ≠ для всего)
[ ] Память выбрана под задачу (1-3 уровня)
[ ] Изменения данных — через propose+confirm
[ ] Стоимость AI логируется с первого дня
[ ] Промпты изолированы от пользовательских данных
```

> **Финальная мысль:** ты учишься не делать финдиректора. Ты учишься **мыслить архитектурой агентов**. Эти 7 паттернов — твой конструктор. Любая автоматизация на Claude собирается из них.
