# 7-40 | Legal Compliance Checklist (152-ФЗ, Россия)

> Тип: Reference
> Фаза: 7 — Legal (Russia)
> Для кого: AI-Архитектор, обеспечивающий юридическое соответствие SaaS-проекта

---

## Философия этого документа

Этот файл — **проверочный список после действия Claude или вашего**. Вы не юрист — вы не пишете политики конфиденциальности с нуля, но вы обязаны убедиться что они есть и корректны. Используйте файл как:

1. **Чек-лист валидации** — перед запуском SaaS пройтись по всем пунктам 152-ФЗ и убедиться что ничего не забыто
2. **Reference для Claude** — загрузить в проект, чтобы Claude сгенерировал шаблоны документов (Политика, Согласие, Оферта) и проверил что они размещены на сайте
3. **Страховка от штрафов** — нарушение = штрафы Роскомнадзора + блокировка сайта

**Принцип работы:**
- Вы — архитектор: знаете, какие данные собирает проект и от каких пользователей
- Claude Code — исполнитель: генерирует документы, добавляет чекбоксы согласия в формы, проверяет наличие
- Этот документ — общий язык между вами

**Как применять:**
```
Сценарий 1: Claude готовит compliance
  Вы → "подготовь SaaS к 152-ФЗ по чек-листу 7-40" → Claude создаёт документы и код

Сценарий 2: Вы валидируете готовый проект
  Вы → открываете чек-лист → галочка за галочкой → находите пропуски

Сценарий 3: Аудит перед релизом
  Вы/Claude → пробегает весь чек-лист → рапортует о готовности
```

> **Важно:** этот чек-лист не заменяет консультацию юриста для сложных случаев (трансграничная передача, медданные, финданные).

## Зачем это нужно

Любой SaaS-проект, работающий с пользователями из России, обязан соблюдать Федеральный закон N 152-ФЗ "О персональных данных". Несоблюдение = штрафы + блокировка сайта.

## Полный чеклист соответствия 152-ФЗ

### Документы на сайте

- [ ] **Политика конфиденциальности** размещена и доступна по ссылке
  - Содержит: перечень данных, цели обработки, сроки, права пользователей, контакты
  - Ссылка: `/privacy-policy`
  - Шаблон: `7-37-PRIVACY_POLICY_TEMPLATE.md`

- [ ] **Правила использования** (оферта / Terms of Use)
  - Содержит: описание услуг, права/обязанности, оплата, ответственность
  - Ссылка: `/terms`
  - Шаблон: `7-38-TERMS_OF_USE_TEMPLATE.md`

- [ ] **Политика cookie**
  - Содержит: типы cookie, цели, как отключить
  - Ссылка: `/cookies`
  - Шаблон: `7-39-COOKIE_POLICY_TEMPLATE.md`

### Согласия пользователей

- [ ] **Чекбокс согласия при регистрации** (обязательный, не предзаполненный)
  - Текст: "Я даю согласие на обработку персональных данных в соответствии с ФЗ-152 и принимаю Политику конфиденциальности и Правила использования"
  - Ссылки — кликабельные, открываются в новой вкладке

- [ ] **Cookie-баннер** при первом посещении
  - Кнопки: "Принять" / "Настроить"
  - Ссылка на Политику cookie

- [ ] **Согласие на рассылку** (если есть email-маркетинг)
  - Отдельный чекбокс, НЕ совмещённый с согласием на ПД
  - Возможность отписаться в каждом письме

### Логирование согласий

- [ ] Факт согласия записывается в БД:
  ```sql
  CREATE TABLE consent_log (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES auth.users(id),
    consent_type TEXT NOT NULL, -- 'privacy', 'terms', 'marketing'
    accepted BOOLEAN NOT NULL,
    ip_address INET,
    user_agent TEXT,
    created_at TIMESTAMPTZ DEFAULT now()
  );
  ```
- [ ] Логи согласий хранятся минимум 3 года

## Уведомление в Роскомнадзор (пошагово)

### Когда нужно подавать

Уведомление **обязательно**, если вы обрабатываете ПД (email, имя, телефон, IP-адрес). Исключения (когда можно НЕ подавать) — узкие: только трудовые отношения, только публичные данные.

**Для SaaS-проекта — подавать обязательно.**

### Шаг 1: Подготовка данных

Перед подачей подготовьте:

| Что нужно | Пример |
|-----------|--------|
| Полное наименование | ООО "Продуктив" |
| ИНН | 7712345678 |
| ОГРН | 1177746123456 |
| Юридический адрес | г. Москва, ул. Примерная, д. 1 |
| Ответственный за обработку ПД (ФИО) | Петров Иван Иванович |
| Email ответственного | privacy@taskflow.ru |
| Телефон | +7 (495) 123-45-67 |
| Дата начала обработки ПД | 01.04.2026 |
| Цели обработки | Предоставление доступа к SaaS-платформе |
| Категории ПД | Email, имя, данные об использовании |
| Категории субъектов | Пользователи платформы |
| Правовое основание | Согласие субъекта, исполнение договора |
| Место хранения | Россия, г. Санкт-Петербург (Beget VPS) |
| Трансграничная передача | Да/Нет (если используете зарубежные API) |
| Меры защиты | Шифрование, RLS, резервное копирование |

### Шаг 2: Подача уведомления

**Портал Роскомнадзора:** https://pd.rkn.gov.ru/

1. Перейти на https://pd.rkn.gov.ru/operators-registry/notification/
2. Нажать "Подать уведомление"
3. Выбрать форму: "Электронная форма уведомления"
4. Заполнить все поля (данные из таблицы выше)
5. Распечатать заполненное уведомление
6. Подписать (ЭЦП или бумажная подпись)
7. Отправить:
   - **Электронно:** через портал с ЭЦП
   - **Бумажно:** распечатать, подписать, отправить почтой в территориальный орган РКН

### Шаг 3: Получение регистрационного номера

- Срок рассмотрения: до 30 дней
- Результат: регистрационный номер вида `XX-XX-XXXXXX`
- Проверить: https://pd.rkn.gov.ru/operators-registry/operators-list/
- Указать номер в Политике конфиденциальности

## Хранение данных в России

### Требование закона

Ч. 5 ст. 18 ФЗ-152: при сборе ПД граждан РФ оператор обязан обеспечить запись, систематизацию, накопление, хранение ПД с использованием баз данных, находящихся на территории РФ.

### Как обеспечить

| Компонент | Где хранить | Решение |
|-----------|-------------|---------|
| База данных (PostgreSQL) | Россия | Beget VPS + Self-hosted Supabase |
| Файлы пользователей | Россия | Supabase Storage на VPS |
| Бэкапы | Россия | Скрипт бэкапа на том же VPS |
| Логи | Россия | PM2 logs на VPS |

### Что можно передавать за рубеж

- Обработка данных (не хранение) — допускается
- Пример: отправка текста в Claude API для AI-анализа — это обработка, не хранение
- Но: основная база ДОЛЖНА быть в РФ

## Права пользователей — как реализовать

| Право (ст. 14-17 ФЗ-152) | Реализация |
|---------------------------|------------|
| Доступ к своим данным | Раздел "Мой профиль" + кнопка "Экспорт данных" |
| Уточнение данных | Редактирование профиля |
| Блокирование | Деактивация аккаунта |
| Уничтожение | Кнопка "Удалить аккаунт" + автоудаление через 30 дней |
| Отзыв согласия | Email на privacy@... или кнопка в настройках |
| Жалоба в РКН | Указать в Политике: https://rkn.gov.ru/treatments/ask-question/ |

### Удаление аккаунта — технически

```typescript
// API Route: DELETE /api/account
export async function DELETE(request: Request) {
  const user = await getUser(request);

  // 1. Деактивировать аккаунт
  await supabase
    .from('profiles')
    .update({ status: 'pending_deletion', deletion_date: new Date(Date.now() + 30 * 24 * 60 * 60 * 1000) })
    .eq('id', user.id);

  // 2. Отозвать все токены
  await supabase.auth.admin.signOut(user.id);

  // 3. Через 30 дней — cron job удалит все данные
  return Response.json({ message: 'Account scheduled for deletion in 30 days' });
}
```
