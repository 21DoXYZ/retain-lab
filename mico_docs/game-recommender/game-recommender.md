# Game Recommender

## Recommendation Contexts

Game Recommender supports multiple recommendation contexts — each designed for a specific placement on your platform. All contexts share the same data pipeline; no additional data uploads are required.

<table><thead><tr><th width="116.0631103515625">Context</th><th width="359.7093505859375">Endpoint</th><th width="251.234375">Description</th><th>Where to use</th></tr></thead><tbody><tr><td><strong>Main</strong></td><td><code>POST /v1/recommendations/main</code></td><td>Primary personalized feed. Uses regional defaults by device type and region when the user has no play history.</td><td>Casino lobby, homepage</td></tr><tr><td><strong>Hidden Gems</strong></td><td><code>POST /v1/recommendations/new_for_user</code></td><td><p>Personalized recommendations excluding games the user has already played. </p><p></p><p>Returns regional defaults for the specified device type and region if the user has no play history.</p></td><td>Lobby, discovery category</td></tr><tr><td><strong>Similar to Your Top Games</strong></td><td><code>POST /v1/recommendations/similar_to_user_top_games</code></td><td>Games similar to the user's most-played games, based on aggregated co-play patterns</td><td>Section next to "Your games"</td></tr><tr><td><strong>Similar Games</strong></td><td><code>POST /v1/recommendations/similar_games</code></td><td>Games similar to a specific game, based on aggregated co-play patterns. No personal data used.</td><td>Under game card, game landing page</td></tr></tbody></table>

## Authentication

All API requests require authentication using a Bearer token in the Authorization header:

```http
Authorization: Bearer YOUR_API_TOKEN
```

Contact your account manager to receive your API credentials.

## Get Access Token

> \
> \*\*Important:\*\* You must specify the \`scope\` parameter with the permissions required for your operations. The scopes must match your product subscription (VIP Intelligence, Game Recommender, or both).\
> \
> Use this token in the Authorization header (\`Bearer {token}\`) for all subsequent API requests.\
> \

### **Note on detailed vs. daily datasets:**

* **Bets:** Send either `bets` (individual transactions) OR `bets-daily` (aggregated daily data), not both
* Choose based on your data pipeline: detailed data provides more granularity, daily aggregates are simpler to prepare
* Models recalculate once per day, so daily aggregates are sufficient for most use cases

## Typical Integration Flow

1. **Authenticate**
   * Get access token: `POST /auth/token`
   * Use the token in `Authorization` header for all requests
2. **Upload Data**
   * Upload user profiles: `POST /v1/data/users`
   * Send betting transactions: `POST /v1/data/bets` (or `POST /v1/data/bets-daily`)
   * Upload in batches (max 1000 records per request)
   * Use cron jobs for continuous daily uploads
3. **Get Recommendations**
   * **Lobby / homepage:** `POST /v1/recommendations/main` — personalized feed per user
   * **Discovery category:** `POST /v1/recommendations/new_for_user` — new games matching user taste
   * **"More like your favorites" section:** `POST /v1/recommendations/similar_to_user_top_games` — games similar to user's top played
   * Cache results 5–15 minutes on the client side
   * Use `limit` and `offset` for pagination
4. **Monitor Service**
   * Check service health: `GET /v1/status`
5. **Ongoing Updates**
   * Continue uploading new betting data daily
   * Update win amounts asynchronously using the same `bet_id`
   * Fetch fresh recommendations as needed

## Error Codes

The API uses standard HTTP status codes:

| Code | Description               |
| ---- | ------------------------- |
| 200  | Success (recommendations) |
| 202  | Accepted (data upload)    |
| 400  | Bad Request               |
| 401  | Unauthorized              |
| 422  | Validation Error          |
| 429  | Rate Limit                |
| 500  | Server Error              |

### Rate Limits

* **Data Upload:** 100 requests/second
* **Predictions:** 1000 requests/second
* **Batch Size:** Maximum 1000 records per upload request
