Tegsoft’s REST APIs

Tegsoft tries to be a strong bridge between the software world and the communication world. We are supplying detailed APIs for allowing many programming languages such as .NET, Java, Php, Python, Javascript to interact with communication services like Voice, SMS, Whatsapp, Webchat.

Many programmers are willing to use JSON-based REST services so we are happy to share our native JSON REST APIs which is documented in this article.

If you need REST XML or SOAP APIs please use the link below to access the related article. https://documenter.getpostman.com/view/5270594/RzthSC1e

Tegsoft provides many REST APIs for managing calls process, sending text messages, managing customer information and much more, to integrate with CRM / ERP / E-Shopping etc. to answer the below requirements.

Receives the call and shows on the agent's screen with using programming skills(Screen-popup)

Introduces customer information to Tegsoft's infrastructure

Receives the calls as different groups such as recognize/unrecognize or in a group or not

Stores the communication history and shows these informations if the customer needs.

Shows customer's informations on the agent's screen

Shows information of the customer waiting in the queue

Monitors the call on the status panel with name

Starts a call by using Tegsoft infrastructure from programming infrastructure with clicking call button

Starts a group call by using Tegsoft infrastructure from programming infrastructure with clicking call button

Tegsoft API infrastructures should be used to see the basic requirements mentioned above.

For additional documentation please check link https://docs.tegsoft.com

What is REST API?

API (Application Programming Interface), is the interface that enables the functions of an application to be accessed and used externally or remotely. The API allows the application on a server to be accessed from different platforms and to return a response.

REST is an architecture that works over the HTTP protocol that provides communication between client and server.

REST API enables applications to communicate by carrying data in many formats, especially XML, JSON, HTML, TEXT, between client and server.

REST API services use different HTTP methods in data transmission. These are GET, POST, PUT, DELETE methods. GET is used for reading, POST is for inserting a new record, PUT is for updating a record, and DELETE is for deleting a record. The HTTP method information, together with the URL called for the HTTP request, is selected as one of the 4 methods and the server determines how the request will affect the recording accordingly.

GET = Read

POST = Create

PUT = Update

DELETE = Delete

Connection check (Health Check) Event

The health check functionality is for overflowing waiting callers if the manager is down for "Timeout (seconds)". The health check functionality is active once "Timeout (seconds)" is provided even if the URL or the "Control frequency (seconds)" is empty.

As long as any healthy communication between Tegsoft and the External Contact Router takes place the connection will be considered as healthy.

If the control frequency is set, Tegsoft will send "Table Synchronization Content" every defined second.

Originate Call

This method is used to originate an outbound call and connect it to a specified extension via PBX. The system first dials the number that will initiate the call. After this number answers the call, it dials the number to be called.

The function takes the Authentication__, extension and destination parameters and accesses the data through ServiceResult.

Authentication : Verified with usercode and password. The user who will use the service must have Webservice access authorization.
extension : Phone number or extension of the caller (agent).
destination : Phone number of the called (customer).
Bridge Calls with Announcements

This method is used to originate two calls, then connect them to each other with announcements via PBX. After DMTF dialing, the system first dials the number that will initiate the call. After this number answers the call, it dials the number to be called. In all these processes, the announcements to be specified by the variables are listened to the parties.

The function takes the Authentication, extension, destination, profile and variables parameters and accesses the data through ServiceResult.

Authentication : Verified with usercode and password. The user who will use the service must have Webservice access authorization.

extension : Phone number or extension of the caller (agent).

destination : Phone number of the called (customer).

profile : CONTEXTID for the Profile that will make outbound call.

variables : A series of channel variables to set on the destination channel.

The optional variables that can be used in this function are given below.

__logDTMF={{DTMFVAR}} ➔ Variable of the DMTF.

{{DTMFVAR}} ={{DTMFVAL}} ➔ Value of the DMTF.

__CONTID={CONTID} ➔ ID number of the contact.

__STARTREC=true/false ➔ Value for the voice recording rule. "true" to start, "false" to not start.

__busyAnnounceIdL2={{BUSYANNID}} ➔ ID number of the announcement that the extension (caller) hears if the destination's phone (called) is busy.

__noanswerAnnounceIdL2={{NOANSANNID}} ➔ ID number of the announcement that the extension (caller) hears if the destination (called) does not answer the call.

__destinationAnnounceId={{DESTANID}} ➔ ID of the announcement the destination (called) hears after answering the call.

__extensionAnnounceId={{EXTANID}} ➔ ID of the announcement the extension (caller) hears after answering the call.

__executeMethodL2={{EXECUTEMETHOD}} ➔ Event to be triggered when destination answers the call.

continueIVRID={{IVRID}} ➔ The parameter used to redirect to a different IVR destination after the call ends.
