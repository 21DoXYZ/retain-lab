# Ранбук онбординга клиента (с нуля)

Флоу самообслуживаемый: клиент идёт по визарду Get started и сам вставляет
свои ключи - Stripe (его биллинг) и Resend (его почта). Платформа нужна только
чтобы завести пространство и снять платформенный dry-run. Время клиента:
~20 минут чистыми плюс ожидание DNS.

## 0. Завести пространство (мы, 2 минуты)

CRM → **Workspaces** → New workspace: название продукта + email владельца.
Система сама делает id пространства (`Hub Content` → `hubcontent`),
ingest-токен, пользователя-владельца в Supabase и строку в crm_users со
скоупом ТОЛЬКО этого пространства. Пароль и токен показываются ОДИН раз -
передать клиенту защищённым каналом.

В новом пространстве нет ничего предустановленного: ни офферов, ни данных.
Каркас кампаний берётся из `_default` и наполняется текстами после опросника.

## 1. Сниппет на сайт (клиент, 5 минут)

Get started, шаг 1: Copy code -> вставить в HTML продукта до `</head>`.
В коде продукта после логина юзера:

    ra.identify(userId, email)          // склейка с биллингом

Обязательное событие ценности - в момент, когда юзер получил результат
(сгенерил видео / завершил экспорт / собрал отчёт):

    ra.track('value_moment')

Полезные дополнительно: `checkout_started`, `cancel_flow_started`,
`contact_update` (контакты+согласия каналов - §6 INTEGRATION-SAAS.md).
Проверка: открыть свой сайт -> в визарде «refresh» -> шаг done (до минуты).
Без сайта под рукой: /demo-site/?tenant=<пространство>&token=<токен из Get started>
(там же кнопка подписки на телеграм-бота - видно, что подставляет сниппет).

## 2. Stripe (клиент, 5 минут, ключи вставляет сам)

Get started, шаг 2:

1. Stripe Dashboard -> Developers -> Webhooks -> Add endpoint -> вставить URL
   ИЗ ВИЗАРДА (он с хвостом пространства) -> отметить 8 событий из списка.
2. Reveal signing secret -> `whsec_...` вставить в поле «Подписной секрет
   вебхука». Без него события отклоняются (fail-closed).
3. Опционально: Create restricted key (Customers/Subscriptions/Invoices/
   Charges/Products/Prices - read, Coupons - write) -> `rk_live_...` вставить
   в поле ниже; проверяем его живым запросом к Stripe. Без ключа не работают
   только скидочные офферы.

Дальше юзеры/стадии/MRR наполняются сами по мере событий; историю можно
подгрузить бэкфилом (по команде Клоду).

## 3. Опросник -> офферы и тексты (клиент, 3 минуты)

Get started, шаг 4: имя продукта, что он делает, URL приложения, юнит ценности
и месячный лимит плана, есть ли API для начислений (+вебхук), триал и его
длина, потолок скидки, можно ли паузить. Можно нажать «Просканировать сайт» -
скрапер прочитает лендинг и прайс и заполнит часть ответов.

Сабмит -> система собирает каталог офферов и тексты всех цепочек под продукт
(AI при наличии ключа, иначе шаблоны; и то и другое проходит валидацию схем).
Посмотреть/поправить: /offers (щедрость, лимиты, свои офферы) и /campaigns
(тексты, тайминги).

## 4. Каналы (клиент, 5-15 минут)

- **Telegram**: @BotFather -> /newbot -> токен в /channel-settings. Канал
  активен СРАЗУ (аккаунтов у провайдеров не нужно). Дальше главное - собрать
  подписчиков: вставить в продукт кнопку `<a data-ra-telegram>...</a>` (сниппет
  сам подставит ссылку с id юзера) либо выдавать ссылку
  t.me/<бот>?start=<их user_id> в письмах. Покрытие = только те, кто нажал
  Start, поэтому предлагать подписку в момент ценности.
- **Email** (клиент заводит СВОЙ аккаунт Resend - это стандарт, §6
  INTEGRATION-SAAS.md): регистрация на resend.com -> API Keys -> ключ Full
  access -> вставить в CRM -> ввести поддомен (mail.бренд.com) -> поставить
  DNS -> Check DNS -> вписать «От кого». Там же скопировать URL вебхука
  доставки в Resend → Webhooks (события bounced/complained/delivered) и
  сохранить его `whsec_...`. Платформенный аккаунт - только по отдельной
  договорённости.
- **SMS/Viber**: заявка альфа-имени (регистрация у оператора 1-3 дня).
- **In-app**: уже active - живёт на сниппете.

## 5. Автопилот (клиент, 2 минуты)

/campaigns: прочитать тексты каждого касания -> Enable (с подтверждением).
Честность: пока действует платформенный dry-run, янтарная плашка об этом
говорит - касания не уходят. Мы снимаем его (SIGNALS_DRY_RUN=0), когда каналы
боевые. Контроль 10% работает всегда.

## После запуска

- Планировщик сам подхватывает новое пространство: джобы (кампании каждые 15
  минут, склейка/контакты/планы :05, скоринг 03:10, uplift Пн 08:00,
  ИИ-аналитик Пн 08:10, причины отмен :20) гоняются ПО КАЖДОМУ заведённому
  пространству.
- Экраны владельца: /home (цифры+статус), /leak-audit (где утекает),
  /users (стадии), /uplift (заработанное против контроля), /insights (ИИ).

## Роли платформы (по команде Клоду)

создание пространства · мок/реальный бэкфил · снятие платформенного dry-run ·
регистрация альфа-имён у DecisionTelecom · WABA-онбординг · платформенный
ключ AI (офферы и тексты) · платформенный Resend - только как исключение.
