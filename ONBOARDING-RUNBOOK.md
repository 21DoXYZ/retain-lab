# Ранбук онбординга клиента (Hub Content, с нуля)

Весь флоу самообслуживаемый: клиент идёт по визарду Get started, платформа
(мы) нужна только чтобы вставить ключи провайдеров в .env. Ожидаемое время
клиента: ~20 минут чистыми.

## 0. Перед созвоном (мы, 5 минут)

- Вход клиента: https://retivo.digital/login, логин `director@crm.local`
  (скоуп = только hubcontent). ВАЖНО: перед выдачей сменить директору пароль
  (сейчас у всех сидов один ротированный) - команда Клоду.
- Если ключи уже есть (Stripe rk_/whsec_, Resend, OpenAI/Anthropic) - отдать
  Клоду, лягут в /opt/retain-lab/.env до звонка.
- Для «красивого» дашборда до реальных данных: `backfill --mock` (по команде).

## 1. Сниппет на сайт (клиент, 5 минут)

Get started, шаг 1: Copy code -> вставить в HTML продукта до `</head>`.
В коде продукта после логина юзера:

    ra.identify(userId, email)          // склейка с биллингом

Обязательное событие ценности - в момент, когда юзер получил результат
(сгенерил видео / завершил экспорт):

    ra.track('value_moment')            // Hub Content может слать generation_completed

Полезные дополнительно: `checkout_started`, `cancel_flow_started`,
`contact_update` (контакты+согласия каналов - §6 INTEGRATION-SAAS.md).
Проверка: открыть свой сайт -> в визарде «refresh» -> шаг done (до минуты).
Без сайта под рукой: /demo-site/?token=<токен из Get started>.

## 2. Stripe (клиент 5 минут + мы)

Get started, шаг 2: Stripe Dashboard -> Developers -> Webhooks -> Add
endpoint -> вставить URL из визарда -> отметить 8 событий из списка.
Прислать нам: signing secret (whsec_...) и restricted key (read-only).
Мы: кладём в .env -> бэкфил истории -> юзеры/стадии/MRR наполняются, шаг done.

## 3. Опросник -> офферы и тексты (клиент, 3 минуты)

Get started, шаг 4: имя продукта, что делает, URL приложения, юнит ценности
(tokens), месячный лимит плана, есть ли API для начислений (+вебхук), триал
и его длина, потолок скидки, можно ли паузить.
Сабмит -> система собирает каталог офферов и тексты всех 6 цепочек под
продукт (AI при наличии ключа, иначе шаблоны). Посмотреть/поправить:
/offers (щедрость, лимиты, свои офферы) и /campaigns (тексты, тайминги).

## 4. Каналы (клиент, 5-15 минут)

- Telegram: @BotFather -> /newbot -> токен в /channel-settings. Работает
  СРАЗУ. Юзеров подключать диплинком t.me/<бот>?start=<их user_id>.
- Email: ввести поддомен (mail.бренд.com) -> после Resend-ключа появятся
  DNS-записи -> клиент ставит -> Check DNS -> вписать «От кого».
- SMS/Viber: заявка альфа-имени (регистрация у оператора 1-3 дня).
- In-app: уже active - живёт на сниппете.

## 5. Автопилот (клиент, 2 минуты)

/campaigns: прочитать тексты каждого касания -> Enable (с подтверждением).
Честность: пока не сняты платформенные ключи, янтарная плашка скажет, что
действует платформенный dry-run - касания не уходят. Мы снимаем его
(SIGNALS_DRY_RUN=0) когда каналы боевые. Контроль 10% работает всегда.

## После запуска

- Пн 08:00 - недельный uplift-отчёт (плюс письмо владельцу при OWNER_EMAIL).
- Экраны владельца: /home (цифры+статус), /leak-audit (где утекает),
  /users (стадии), /uplift (заработанное против контроля).

## Роли платформы (по команде Клоду)

мок-бэкфил · вставка ключей · снятие платформенного dry-run · смена пароля
директора · регистрация альфа-имён у DecisionTelecom · WABA-онбординг.
