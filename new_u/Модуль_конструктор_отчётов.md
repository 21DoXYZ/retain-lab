# Кандидат в модуль 06: Конструктор отчётов («замена аналитика»)

_Статус: концепт, в разработку пока не берём. Источник: звонок с Василием 13.07 (показал живой Power BI и процесс заказа отчётов). Реакция Василия на идею: «Великолепно. Да. Ценность — что я могу собрать этот набор данных, может быть, даже без аналитика»._

## Боль (подтверждена практикой Василия)

1. **Аналитик — дорогой и недоступный ресурс:** от €4 000/мес, поиск занимает 4–6 месяцев, перекупают за +$500 к зарплате. У множества проектов аналитика нет вообще (Forabet — топ-5 Индии — без CRM, «Power BI настолько ужасный, что передать не могу»).
2. **Процесс сегодня:** заказчик пишет ТЗ текстом → отдел аналитики думает, как реализовать → собирают данные → выводят в Power BI → ждут днями. Отчёты не стандартизированы — «каждый суслик в поле агроном».
3. **Отчётов куча под каждое кресло:** продуктовый, ретеновский, виповский, саппорт, колл-центр, бонусы, SMM, «борды смотрят только деньги», вплоть до индивидуальных зарплатных с доступом одному менеджеру.
4. Power BI ещё и «оптимизируют» пиратски: тестовый период 60–90 дней → сносят → продлевают.

## Решение

**«Волшебная кнопка»: пишешь ТЗ отчёта обычным текстом → система собирает отчёт за минуты.** (Это единственное место продукта, где уместна LLM-прослойка: текст-ТЗ → конфигурация отчёта; сами данные считает наша аналитика, без галлюцинаций.)

Требования из разговора:
1. **Сводные таблицы как в Excel:** группы фильтров с изменяемым порядком разрезов — выбрал сначала бренд → день недели, или сначала тип трафика → месяц — таблица перестраивается.
2. **Сохранение отчётов**: имя («Вася-продукт»), автор, доступы — личный / общий / по ролям. Рекомендация Василия: лучше один канонический отчёт на компанию, чем 18 почти одинаковых — предусмотреть «официальные» отчёты и черновики.
3. **Доступ по ролям**: оператору — ничего или один его отчёт (кейс: зарплатный отчёт менеджера видит только он); руководителям — свои наборы.
4. **⚠️ Историческая корректность сегментов** (типичная ошибка Power BI, которую все проглатывают): «VIP-игроки в феврале» = те 18, кто был VIP в феврале, а НЕ текущие 180, спроецированные назад. Все временные срезы считаются по состоянию сегмента на тот момент.
5. Частота обновления по выбору: раз в день / неделю / месяц, исторические vs текущие данные.

## Продажа

- Питч: **«отчёт за 7 минут вместо аналитика за €4 000 в месяц, которого ещё полгода искать»**. Окупает подписку целиком сам по себе.
- Закрывает возражение «у нас уже есть дашборды»: у вас есть ГОТОВЫЕ дашборды — а у нас каждый руководитель собирает СВОЙ отчёт без очереди к аналитикам.
- Синергия: данные уже в системе (36 срезов, вся схема) — модуль почти не требует новых данных, только интерфейс.

## MVP-скоуп (когда возьмём)

1. Сводная таблица по существующим данным: выбор метрик + 2–3 уровня группировки + фильтры + период.
2. Сохранение/шаринг отчёта, доступ по ролям (роли уже будут из ТЗ колл-центра).
3. Экспорт CSV/XLSX.
4. Текстовое ТЗ → черновик отчёта (LLM-прослойка) — фаза 2.
5. Исторические сегменты — с первого дня (это дифференциатор, а не полировка).
