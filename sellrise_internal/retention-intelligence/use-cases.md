# Retention Intelligence — Use Cases

Единица решения — **отдельный игрок**, не когорта. Каждому активному игроку система
собирает связку скоров и превращает её в одно действие с конкретным оффером и каналом.

## Формат решения (сигнал по игроку)

```json
{
  "casino_player_id": 40,
  "pred_ltv_d90": 12345.60,
  "p_churn_30d": 0.87,
  "p_next_deposit": 0.42,
  "ltv_tier": "D",
  "recommended_action": "SAVE",
  "recommended_bonus": "cashback",
  "priority": 9876
}
```

Действия — машиночитаемый enum (см. [Predictions Delivery](../integration/predictions-delivery.md)):

| Действие | Кому | Логика |
|---|---|---|
| `CONVERT` | один депозит, высокий P(второго) | дожать второй депозит (repeat + ladder) |
| `NUDGE` | активен, близок к следующему депозиту | лёгкий нудж по ladder-скору |
| `SAVE` | ценный + высокий риск оттока | удержать: кэшбэк/менеджер, пока не ушёл |
| `WINBACK` | уже молчит, ценность оправдывает возврат | реактивационный оффер |
| `NURTURE` | новичок с высоким LTV-прогнозом | растить: онбординг, ранний VIP-трек |
| `MONITOR` | остальные | не трогать (не сжигать бонусы и доверие) |

`priority` ранжирует всю базу — команда работает список сверху вниз в пределах ёмкости.

---

## Use Case 1: конверсия в повторный депозит

Топ по `p_2nd_ml` среди «однодепозитников» + `rec_bonus` из bonus-модели → точечный
оффер в первые 48 часов. Дешевле всего поднять repeat-rate именно здесь: игрок ещё
«тёплый», а оффер персональный, не когортный.

## Use Case 2: удержание ценных (SAVE)

`p_churn` выше порога × `ltv_tier ∈ {C, D}` → очередь удержания: колл-центр или
менеджер, скрипт и бонус — из рекомендации. Дешёвые тиры при том же риске уходят в
автоматические каналы или `MONITOR` — экономия бонусного бюджета на тех, кто вернулся
бы сам или не окупит возврата.

## Use Case 3: экономия бонусного бюджета

Инверсия классики: не «всем ушедшим по 20% кэшбэка», а бонус только там, где скор
говорит, что он меняет исход. `MONITOR` — это тоже решение: не спамить лояльных
(спам сам провоцирует отток), не субсидировать «мертвяков».

## Use Case 4: выгрузки колл-центру

Ежедневные сегментные списки (at-risk / dormant / churned / never-deposited) со
скорами, приоритетом и рекомендацией — прямо из дашборда, XLSX. Исход звонка оператор
фиксирует в той же системе; реакция (депозит/игра ≤7 дней после контакта) считается
автоматически — видно, какие действия и скрипты реально работают.

## Use Case 5: связка с VIP Intelligence

Ядро ведёт игрока до порога VIP (NURTURE по высокому LTV-прогнозу), дальше подхватывает
[VIP-линейка](../vip-intelligence/use-cases.md): ранний менеджер, депозитный риск,
фильтр бесперспективных. Скоры обоих контуров живут в одной карточке игрока.
