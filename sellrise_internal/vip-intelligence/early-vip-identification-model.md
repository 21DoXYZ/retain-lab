# Early VIP Identification Model

## Обзор

Модель по поведению **первой недели после первого депозита (FTD, дни 0–7)** предсказывает,
станет ли игрок VIP — достигнет порогового уровня (Gold) по накопительным успешным
депозитам — в течение 90 дней.

Традиционно VIP «замечают», когда он уже накопил порог — через недели, когда игрок либо
уже лоялен, либо уже ушёл к конкуренту. Модель находит кандидатов в первые дни —
в фазе исследования платформы, когда персональный контакт даёт максимальный эффект.

> **Конфигурация.** Порог VIP (уровень Gold лестницы оператора), окно наблюдения (7 дней)
> и горизонт (90 дней) — параметры реализации, настраиваются под правила оператора.

### Ключевые выгоды

- Идентификация будущих VIP за дни вместо недель
- Раннее закрепление за VIP-менеджером — до того, как игрок «распробовал» конкурентов
- Концентрация приветственных бонусов и внимания на игроках с реальным потенциалом
- Из тысяч новых депозиторов — короткий ежедневный список кандидатов

## Определения

**Население:** депозиторы (`account_type='normal'`). Для обучения — только игроки,
у кого окно FTD+90 полностью попадает в имеющиеся данные (метка наблюдаема).

**Таргет:** накопительные успешные депозиты за 90 дней от FTD достигли порога Gold
(см. таблицу тиров в [VIP Churn Prediction Model](vip-churn-prediction-model.md)).

## Требования к данным

- Минимум **6 месяцев** истории с достаточным числом конверсий в VIP (Gold — редкое
  событие, ~3% депозиторов; для устойчивого обучения нужен объём).
- Критично: депозиты со статусами, `users` (даты регистрации и FTD, сумма FTD, атрибуция);
  рекомендуется: ставки/выигрыши (`game_transactions`), выводы.
  Подробно — [Data Requirements](../integration/data-requirements.md).

## Как устроена модель

Защита от утечки: признаки считаются **только из окна [FTD, FTD+7]**, метка — из
[FTD, FTD+90]. Валидация по времени: ранние FTD → train, поздние → test.

**Признаки (19):** сумма FTD, лаг регистрация→FTD, депозиты дня 0 и недели (суммы,
количество, максимум), выводы недели, ставки/оборот/средняя ставка/число разных игр/
активные дни/фриспины/ночная доля/чистый результат за неделю + категориальные:
основной провайдер недели, способ оплаты, тип аффилиата, страна.
Алгоритм — градиентный бустинг (CatBoost).

## Качество (на реальных данных, тест — поздние FTD)

| Метрика | Значение |
|---|---|
| ROC-AUC | **0.945** |
| PR-AUC | 0.662 (база 0.029) |
| Brier | 0.067 |
| Top-5% по скору | **68% реально стали VIP — lift ×13** к базе |

> **Как читать.** Каждый 20-й новый депозитор попадает в топ-5% скора, и двое из трёх
> оттуда действительно доходят до Gold. Это рабочий ежедневный список для VIP-менеджеров.

## Работа с предсказаниями

Модель возвращает вероятность 0–1 (`p_early_vip`) для каждого депозитора.

**Выбор порога = ёмкость команды:**

- Сколько новых игроков в день менеджеры реально могут взять в работу? Берите топ-N по скору.
- Низкий порог → шире воронка кандидатов, больше ложных срабатываний (норм для
  автоматических приветственных цепочек).
- Высокий порог → короткий список для персонального контакта (звонок, личный менеджер).

**Прогрессивное уточнение:** скор пересчитывается ежедневно — по мере накопления
поведения внутри первой недели предсказание уточняется.

## Ограничения

- Игроки моложе 7 дней от FTD скорятся по неполному окну — скор уточняется день ото дня.
- Редкий таргет: абсолютная вероятность калибрована хуже, чем ранжирование; работайте топом списка.
- Изменение порога VIP (например, Gold → другой уровень) требует переобучения.
- Модель обучена под конкретное казино и её трафик-микс; смена источников трафика
  (новые аффилиаты/GEO) может временно снижать точность до переобучения.

1. **Данные:** [Real-time Event Ingestion](../integration/realtime-event-ingestion.md) / [Batch Data Ingestion](../integration/batch-data-ingestion.md)
